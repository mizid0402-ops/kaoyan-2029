# 考研学习 AI 系统（kaoyan-2029）

> 一个**本机运行、以数据为准**的考研备考系统：把考纲拆成知识树，把历年真题挂到知识树上，
> 在"每天就这么多时间"的硬约束下，确定性地算出今天复习什么、新学多少、欠了多少。
>
> 当前服务的考试：**2029 届（2028 年 12 月初试）· 数学一 + 英语一 + 408 计算机统考**，严格按零基础起步。
> 部署：纯本机单用户，本地文件是唯一真相源。测试按 `AGENTS.md` 的验证范围执行；
> 工作包只跑相关模块，全量测试由决策者在提交前统一执行。

## 〇、只想要数据：考研树 / 真题索引 / 考频权重

> 只想拿数据的人看这一节就够了，不必读下面全文。数据全是纯文本（YAML / JSON），
> 不需要安装任何依赖就能打开；要跑校验命令只需要 Python 3.12。

```powershell
git clone <仓库地址> kaoyan-2029
cd kaoyan-2029
```

| 要拿的东西 | 路径 | 里面是什么 |
|---|---|---|
| **考研知识树** | `data/structured_materials/<科目>/knowledge_tree.yaml` | 408：403 个生效节点 + 2022 大纲补充视图；数学一：69 个节点 + 123 条「考试要求」编号条目；英语一：24 个结构节点。每个节点都能追到源文件的原文位置与 SHA-256 |
| **真题索引**（题目元数据） | `data/exam_questions/*.json` | 逐卷逐题的题号、题型、可核实分值、答案来源与原卷定位。**只有元数据，不含题干原文** |
| **卷面形状** | `data/paper_shapes/<科目>.yaml` | 每卷题量、题型、答案字母与可验证分值；没核实到的分值保持 `unverified`，不猜成实测值 |
| **考频权重**（题 → 知识点） | `data/review_weights/topic_weights.json`；逐题打标在 `data/review_weights/coder_outputs/` | 章节级考频权重。每道题的归属由三个模型独立打标后按置信度聚合，可从打标产物逐值重算 |
| **原始资料清单与来源** | `data/materials.yaml` | 61 份原始资料（大纲、真题卷、参考答案、转录页…）的来源地址、来源可信度档与**权利状态**（能否存储 / 展示 / 再分发） |

**自己校验一遍**（可选）：三条命令分别核对"节点能追到源文件字节与原文位置""真题索引自洽""权重可复现"。

```powershell
py -3.12 tools/verify_tree.py data/structured_materials/cs408/knowledge_tree.yaml --workspace kaoyan.workspace.yaml
py -3.12 tools/verify_408_index.py
py -3.12 tools/aggregate_topic_weights.py --check
```

**真题原文、大纲正文、扫描件不在本仓库里，也不转载。** `data/materials.yaml` 为每一份登记了
来源地址与权利状态（61 份都有公开来源地址；台账里"允许再分发"的条目是 **0** 份，所以这里只放元数据）。
本地缺哪一份，可以让程序按台账重取：

```powershell
py -3.12 tools/fetch_all_from_ledger.py --check   # 先看缺哪些、哪些允许取回
py -3.12 tools/fetch_all_from_ledger.py           # 再下载到 data/raw_materials/（该目录不进 git）
```

正文请通过你自己的合法渠道获取；使用前请读文末[免责声明](#七免责声明与诚实声明)。

### 这一节背后的做法（可照搬到别的科目 / 别的考试）

1. **原文不进仓库，只进"能核验的元数据"。** 知识树节点必须能在源文件里定位到原文
   （`sources[0].locator.quote_ref`），且 `sources[0].sha256` 等于源文件真实哈希；
   真题只记题号、题型、分值、答案来源与原卷定位。这样仓库可以公开发布，又不搬运别人的正文。
2. **来源与权利是两条轴，都登记在 `data/materials.yaml`**：`rights`（允不允许用：存储 / 展示 / 再分发）
   与 `provenance.source_tier`（该不该信：`official` / `official_publisher` / `university` /
   `trusted_reprint` / `community_archive`，不填按最弱档）。"没说的可信度"不等于"高可信度"，
   "能结构化"不等于"能再分发"。
3. **结论要能重算，而不是靠信任。** 权重能从逐题打标逐值重算，索引有独立校验命令，节点有哈希与原文定位；
   谁拿到仓库都能自己验一遍（上面三条命令）。
4. **拿不到的部分给路径，不给文件。** 原文在台账里只留来源地址，读者按清单自行获取
   （`tools/fetch_all_from_ledger.py`），合规责任留在使用者自己这边。

## 一、它能做什么

### 1. 考研知识树：把考纲变成可计算的节点

| 科目 | 节点数 | 来源 | 当前状态 |
|---|---:|---|---|
| 408 计算机统考 | 403（生效树）+ 410（含 2022 旧大纲来源的补充视图） | 2026 年考纲原文逐条提取 | `extracted` |
| 数学一 | 69（3 科 × 22 章 × 考试内容 / 考试要求） | 两份独立全文转录交叉验证 | `extracted` |
| 英语一 | 24（结构树，刻意做粗） | 2026 年考纲目录 | `extracted` |

- 每个节点都能追溯到源文件中的原文位置与 SHA-256；**AI 不得凭"自己知道的 408"补节点**。
- 节点状态机 `raw → extracted → reviewed → approved`，后三步只能由人推进——AI 建的树永远停在 `extracted`。
- **大纲会变**：新一年大纲出来，登记为新版本 + 写一份"变化映射"（拆分 / 合并 / 改名 / 删除 / 新增），
  复习队列可一键按映射迁移（`ky review-queue migrate`），迁移后自动检查没有指向不存在知识点的复习项。

### 2. 真题索引 + 考频权重：知道每个知识点"考得多不多"

- 从工作区注册表读取各科、各年及各出题单位的真题索引，记录题号、题型、可核实的分值、答案来源与原卷定位。
  **只存元数据，不存题干原文**（版权）；408 选择题答案从两个独立锚点读出并交叉核对。
- 每道题 → 知识点的归属由三个不同模型**独立打标、按置信度加权投票**：一致时权重集中在一个节点，
  分歧时自动变成"这题跨了两个点"的权重分布，不强行二选一。汇总成章节级考频权重。
- 聚合是确定性的：`py -3.12 tools/aggregate_topic_weights.py --check` 可从原始打标产出逐值重算出现有权重文件；
  追加新一年只改数据，旧年份的逐题结果逐字节不变。

### 3. 复习调度：在预算内排复习，超出的明确记成欠账

- **容量裁剪核**：给定每日总时长与各科权重，确定性地选出今天复习哪些项；
  放不下的进入 `deferred`（延期，到期日不偷偷改）或 `unschedulable`（单项太大，提示拆分），**欠账显式可见**。
- **复习推进**：阶梯间隔 + SM-2。复习"完成"只认有锚点的核对结果（做真题 / 做练习 / 默写后对照）；
  同一条完成记录重放、补录都只算一次。
- **自评两档**：默认严格档，自评不影响间隔；宽松档里自评"不会 / 模糊"可以缩短间隔，
  但自评"会"必须先答一道系统从真题索引里挑出的核对题——**自评永远不能拉长间隔**。
- 每日计划、完成事件、月度对账全部原子落盘；完成记录与月结写一次不可改。

### 4. 英语词汇通道

- 词表来自历年真题原文统计，按词族考频排序；命令按显式数量预览候选词，
  可附出处证据（哪年哪卷哪页）。每日数量由规划者决定。
- 已投放的词记在你的完成事件里；参考词库只读、可整库替换。

### 5. 状态查看与规划者接口

- `ky snapshot`：只读汇总各科知识点数、今日到期、欠账分钟、距考试天数、词汇余量——**只陈述状态，不给建议**。
- SQLite 只读投影（`py -3.12 -m ky.projection`）：知识树、真题、权重、补充视图一次性可查，可随时删掉重建。
- **规划者端口**：系统生成带哈希的日计划或路线输入包，AI 或人据此写提案放进 `staging/`，
  系统校验来源、输入是否过期及写入护栏，通过后才落盘，并记录提案者与输入依据。
  换一个 AI 规划者，系统这一侧不用改。

## 二、优势区间：什么情况下它最有用

| 场景 | 为什么适合 |
|---|---|
| **时间很紧、周期很长**（每天 1–3 小时、备考一两年） | 复习量会随时间滚雪球：每天新学 5 条、每条复习 5 分钟，稳态下光到期复习就要 125 分钟 > 120 分钟预算。系统从第一天就按容量裁剪，欠账是算出来、看得见的，而不是某天突然崩掉。 |
| **零基础 / 自学，判断不了自己会没会** | 自评不能推迟复习；"会不会"由做题结果决定。宽松档允许你说"不会"来多复习，但说"会"要先过一道真题。 |
| **统考科目**（408、数学一、英语一；其他统考如农学 314/315 同理） | 有公开真题可挂到知识树上，考频权重有数据支撑，复习优先级不是拍脑袋。 |
| **想让 AI 帮忙排计划，但不想让 AI 乱改学习记录** | AI 零特权：AI 的产物只能进 `staging/`，经程序校验后才生效；AI 不能写完成状态、考频、能力画像。 |
| **要年复一年追加数据** | 新真题、新大纲、新一批打标、新科目，都是"放数据 + 注册表登记一行"，不改代码；每一步都有契约测试守护。 |
| **在意隐私与可控** | 纯本机、本地文件为真相源，数据库只是可重建的投影；任何数字都能追到源文件与哈希。 |

## 三、它不擅长 / 还做不到的

- **不是题库，也不是讲义**：不存题干和解析原文，看题要去原卷；它告诉你"该练哪一块、练哪几道"。
- **知识树尚未对照纸质官方大纲复核**：数学一、英语一的来源是第三方全文转录；全部节点停在 `extracted`，
  要等拿到官方大纲、由人逐章确认后才能升级。
- **英语一树很粗**（24 个节点），题目→知识点的权重区分度明显低于 408。
- **各校自命题专业课**：数据结构上已支持（出题单位、卷面登记），但仓库里还没有任何自命题数据。
- **参数还是估计值**：复习间隔阶梯、单次复习耗时、每日 120 分钟等，要用真实记录校准。
- **图形界面只有一个"今天"页**：`py -3.12 -m ky web`（只绑本机 127.0.0.1）能看今天要复习什么、
  改某天可用分钟、记录当天结果与补推进；复习队列页、路线与复盘页、图表页还没有做进网页，
  仍走命令行或离线 HTML 图表。政治尚未启用（按计划考前 12 个月启动）。

## 四、上手

> 本机 `py` 启动器不回显子进程输出，**一律用 `py -3.12`**。

```powershell
# 今天复习什么、还剩多少新学时间（只读，不写任何东西）
py -3.12 -m ky preflight --config tests/fixtures/config/config-minimal.yaml `
    --items tests/fixtures/reviews/reviews-overloaded.yaml --date 2026-09-12

# 当前状态总览（复习队列缺省取注册表登记的 state.review_queue）
py -3.12 -m ky snapshot --config tests/fixtures/config/config-minimal.yaml --json

# 本学期第 3 周课表图（离线 HTML，输出目录来自 products.charts）
py -3.12 -m ky chart week --week 3

# 生成截至昨天的近四周学习进度图
py -3.12 -m ky chart progress

# 生成四档能力、目标差距、掌握树与薄弱点画像
py -3.12 -m ky chart ability

# 学完知识点后入复习队列（次日第一次复习）；学完一整块可用 --leaves-under <节点>；先加 --dry-run 看看
py -3.12 -m ky learn --date <日期> --knowledge-point <知识点 ID>
# 今天每个复习项做哪道题（学过 → AI 改编题，掌握中起 → 真题原题；记录时照输出填 check 与 question_ref）
py -3.12 -m ky review-questions --date <日期>
# 给某个知识点生成改编题：先出输入包，AI 按 prompts/adapted_questions.md 写到 staging/question_bank/，再提交
py -3.12 -m ky planner-input --kind adapted-questions --knowledge-point <知识点 ID>
py -3.12 -m ky question-bank submit --from-staging staging/question_bank/<名>.yaml --dry-run
# 做题发现改编题有问题（答案错、超纲、无关）就停用，之后不再出
py -3.12 -m ky question-bank retire --question <题号> --reason "<原因>" --date <日期>   # review-questions 输出里有可直接复制的整行

# 今天的英语单词（只读预览；末尾给出可粘进完成事件的片段）
py -3.12 tools/daily_words.py --count 15 --show-evidence

# 记录今天做了什么（完成事件写一次不可改；加 --review-store 才推进复习队列）
py -3.12 -m ky day-plan record --config <配置> --done <完成事件.yaml> --review-store data/review_queue
py -3.12 -m ky day-plan advance --date <日期> [--store <计划目录>] [--review-store <队列目录>] [--config <配置>]

# 数据自检
py -3.12 tools/verify_408_index.py                    # 真题索引
py -3.12 tools/aggregate_topic_weights.py --check     # 考频权重可复现
py -3.12 -m ky review-queue check                     # 复习项都指向存在的知识点
py -3.12 tools/fetch_all_from_ledger.py --check        # 离线检查台账中的本地资料；去掉 --check 才尝试重取缺失文件

# 周期复盘（M28，可选）：先写复盘设置并在本地补充注册表登记 settings.pacing（见 contracts/pacing_review.md §2）
py -3.12 -m ky pacing status                                   # 当前基数来源、当前周期、还没出报告的周期
py -3.12 -m ky web [--port 8730] [--no-open]                    # 打开本机“今天”视图
py -3.12 -m ky pacing report --cycle-end <周期终日>              # 周期结束后出报告（写一次，不改写）
py -3.12 -m ky planner-input --kind pacing --cycle-end <周期终日> # 给 AI 的输入包，写到 staging/inputs/
#   AI 按 prompts/pacing_review.md 写方案到 staging/pacing/<名>.yaml
py -3.12 -m ky pacing submit --from-staging staging/pacing/<名>.yaml --dry-run   # 先看变更摘要
py -3.12 -m ky pacing submit --from-staging staging/pacing/<名>.yaml             # 确认后生效（中断了就重跑同一命令）

# 路线（可变时间线）：AI 按 prompts/route_planning.md 写提案到 staging/routes/<名>.yaml，用户同意后提交
py -3.12 -m ky planner-input --kind route --date <日期>
py -3.12 -m ky route submit --from-staging staging/routes/<名>.yaml
py -3.12 -m ky route show

# 决策者提交前统一运行全量回归测试；工作包只运行任务书指定模块
py -3.12 -m unittest discover -s tests -t .
```

所有数据文件的位置登记在仓库根的 `kaoyan.workspace.yaml`（工作区注册表）；换一棵树、换一个词库、加一年真题，改这里即可。

## 五、设计原则

### 三条不可逾越的硬不变量

1. **唯一真相源**：本地文件与审计事件是权威状态；SQLite 只是可删除重建的投影，Web 首版只读。
2. **AI 产物零特权**：AI 输出先进 staging，经程序校验后 apply；AI 不得直接写能力图谱、出现频率、任务完成状态。信任边界与 apply 执行者约束见 `contracts/planner_port.md` 的 Trust boundary 一节。
3. **自评零特权**：复习完成只认有锚点的核对结果（决议 D3）；默认严格档里自评不影响间隔。
   用户授权的修订（决议 D9）：宽松档里自评"不会 / 模糊"可以**缩短**间隔，但自评**永远不能拉长**间隔——
   自评"会"要先答一道系统出的题，答题结果才作为核对结果推进。

### 拼图式模块（决议 D7：可维护性与可读性优先）

系统拆成约 25 块，块与块之间只通过写成文档的**端口规格**（`contracts/*.md`）咬合，每个端口配契约测试
（`tests/contract/`）。任何一块都可以单独替换：照规格实现、跑通契约测试即可接上。
总图见 [`docs/模块地图.md`](docs/模块地图.md)。

### 模块替换速查

下表说明每块的替换边界。对应规格、实现文件、注册表键和精确验收命令见
[`docs/模块地图.md`](docs/模块地图.md)；换实现时先保持端口与用户可见输出，再运行该行的契约测试。

| 模块 | 职责 | 替换时要守住的边界 |
|---|---|---|
| M0 工作区注册表 | 发现科目与数据位置 | 保持 `contracts/workspace.md` 的路径、版本、feature 开关和错误语义 |
| M1 资料采集与重取 | 获取并校验原始资料 | 按台账 URL 与哈希恢复缺失字节；不得覆盖已有资料 |
| M2 资料台账 | 验证资料身份与权利 | 保持 `contracts/ledger.md` 的字段、证据等级与完整性报告 |
| M3 引用门禁 | 判定资料能否被知识树引用 | 保持 `contracts/citation_gate.md` 的拒绝理由 |
| M4 知识树 | 解析、校验及迁移知识节点 | 保持树、层级和版本映射端口；节点必须能追溯来源 |
| M5 真题索引 | 记录试卷题目元数据 | 按注册表读取索引，保持题号、来源与校验结果 |
| M5′ 卷面形状 | 登记可核实的卷面结构 | 未核实分值保持 `unverified`，不猜作实测值 |
| M6 题目权重 | 聚合题目到知识点的编码 | 相同批次输入产生相同权重与报告 |
| M7 词汇参考库 | 提供只读词汇候选 | 词汇投放状态由 M13 保存，不写回参考库 |
