## 0. 结论先行

**一句话**：单个模块内部的质量很高（契约严格、确定性、fail-closed、测试和变异测试齐全），
但**模块之间的"接缝"还没有被设计成可替换的**——契约只存在于 Python 代码里、文件路径写死在各模块中、
同一实体有两套"权威"、"当天的 AI"这个核心角色没有接口定义。
按"任意一部分可替换"的标准衡量，**当前大约只有排程纯函数（预算切分、复习裁剪）达到了可替换水平**。

### 0.1 阻断"可替换"目标的 5 个问题（P0）

| # | 问题 | 证据 | 后果 |
|---|---|---|---|
| A1 | **没有语言中立的契约**。所有文件格式只存在于 Python 的 `frozenset` 白名单里；`ky/contracts/` 是空壳 | 【读码】`ky/contracts/__init__.py` 自述 "Nothing in this package is used yet"；原计划的 `*.schema.json` 从未交付 | 想用别的语言/别的实现替换任何一块（前端、AI 规划者、存储），都没有可对照的规格 |
| A2 | **路径写死**，没有"当前生效文件"的统一配置 | 【读码】`ky/projection/__init__.py` 写死 5 个输入路径；`state_snapshot.py`、`vocab_channel.py` 用 `Path(__file__).parents[2]`；5 个 tools 写死 `F:\workspace\kaoyan-ai-system`；`knowledge_tree_weighted.yaml` 内含 `C:\Users\Lenovo\AppData\Local\Temp\...` | 换一份树/换一个词库/换目录 = 改代码，而不是改配置 |
| A3 | **同一实体两套权威**：408 知识树 | 【读码】`state_snapshot` 读 `cs408/knowledge_tree.yaml`（403 节点），`projection` 读 `cs408/knowledge_tree_multisource.yaml`（410 节点）；该目录下共 5 个树版本，没有登记哪个生效 | 快照说 408 有 403 个点、网页说 410 个；替换树时不知道该替换哪一个 |
| A4 | **复习队列读写格式分裂，闭环在 CLI 层断开** | 【实测】`ky day-plan record --review-store` 把推进后的复习项写进 `ReviewShardStore` 分片目录；`ky preflight`/`ky snapshot` 的 `--items` 只收扁平 YAML，传同一目录报 `contract violation: file does not exist`。`load_review_queue()` 能读两种格式，但 CLI 没用它 | "完成事件→推进队列→明天再排"这条主链路，用命令行走不通 |
| A5 | **"当天的 AI"不是一个组件** | 【读码】阶段②决议把分钟数、词数、比例、切换点全部交给"负责当天的 AI"，但仓库里没有该 AI 的输入包定义、输出 schema、staging 目录、apply 命令；`DayPlan`/`CompletionEvent` 没有 `actor`/来源字段 | 硬不变量②"AI 产物零特权、先进 staging"目前**只靠纪律，没有代码**；也无法"换一个 AI" |

### 0.2 与项目自己定的硬不变量冲突（P1）

- **B1 自评驱动到期日**：`ReviewCompletion.quality`（0–5）注释写明是 *self-assessed*，却直接决定 `interval_days` 和 `due_date`（`completion.py:90–190`）。这与硬不变量③"自评不能改到期日"正面冲突。
- **B2 参考数据与学习状态混存**：冻结的 `eng1_vocabulary.sqlite` 里有 `delivery_log`（【实测】15 行，属于学习状态），且有 4 个写入口（阶段②残项 R1）。
- **B3 投影绕过契约**：投影用 `yaml.safe_load` 直接读树（不经 `load_knowledge_points`，重复键保护、字段校验全部绕过）；真题索引和权重表在 `ky/` 里**没有契约**，只有 `tools/verify_*.py`。

### M0 契约基础设施（横切）

- **功能预期**：每一种在模块之间流动的文件（配置、复习项、知识点、台账、真题索引、权重、日计划、完成事件、月结、投影表）都有**一份与实现语言无关的规格**，外加统一的加载/校验入口。替换者只要满足规格就能接上。
- **现状 🟡**：校验本身做得很好（未知键拒绝并给路径、NaN 拒绝、YAML 重复键 fail-closed、`schema_version`）。但：
  - 规格**只存在于 Python 代码**（`ky/models.py:55–86`、`knowledge_point.py:60–68`、`completion.py:193–195`、`day_plan_store.py:65–69` 的 `frozenset`）；
  - `_require_mapping` / `_reject_unknown` 这组辅助函数在 `models.py`、`knowledge_point.py`、`completion.py`、`day_plan_store.py` 各写了一份；
  - 真题索引、权重表、词汇库 schema、投影表**没有 ky 层契约**。
- **替换时必须满足**：（目前无法表述——这正是问题所在。）
- **建议**：新建 `contracts/` 放 JSON Schema（或至少一份 Markdown 规格 + 示例文件），每种文件一份；Python 校验器保留（跨字段语义 JSON Schema 表达不了），但加一条测试：**所有 fixture 同时通过 JSON Schema 与 Python 校验器**，防止两者漂移。

### M1 资料采集

- **功能预期**：从公开 URL 取回资料，记录 HTTP 状态、最终 URL、字节数、响应 sha256、编码。
- **现状 ✅**：`tools/fetch_evidence.py`，另有一批 `probe_*`、`register_*` 工具。
- **输入/输出**：URL 列表 → `cache/evidence/<batch>/*.html` + `index.json`；登记后落 `data/raw_materials/…`。
- **审查发现**：
  - 遗留项仍在：文本页被解码重编码落盘，**摘录与响应字节之间没有密码学绑定**（交接文档 §8.1-4）。
  - **没有"按台账一键重取全部原始资料"的工具**。`data/raw_materials/` 被 gitignore，而知识树溯源、若干测试依赖这些文件；只有 `restore_408_papers.py` 覆盖 7 个 408 PDF。【实测】干净克隆下测试大面积失败（见 M22）。
- **替换时必须满足**：产出文件路径 + sha256 能被 M2 台账登记并通过 `ky ledger` 完整性校验。

### M2 资料台账

- **功能预期**：一份资料一行，`rights`（能不能用）与 `source_tier`（该不该信）两轴独立；本地文件记本地 sha256。
- **现状 ✅**：`ky/ledger/material.py` + `data/materials.yaml`。【实测】`ky ledger` exit 0，49 条，24 条权利 `unknown`。
- **审查发现**：
  - `SUBJECT_IDS` 写死在 `material.py:105`，加科目要改代码。
  - 49 条全部 `review_status: verified`，而其中 24 条权利未明——"verified"的含义（字节核实 vs 权利核实）建议在规格里写清楚。
- **替换时必须满足**：`ky ledger --ledger <file>` 校验通过；`storage.sha256` = 本地文件哈希。

### M3 引用门禁

- **功能预期**：知识点的 `sources` 必须指向台账里 `may_be_structured` 的资料，且哈希一致。
- **现状 ✅**：`ky/ledger/citations.py`，依赖 M2 + M4 契约。
- **可替换性 B**：接口是函数级的，边界清楚；依赖 M4/M2 的 Python 类型。

## 4. 架构审查结论

### 4.1 做得好的地方（应当保留）

1. **真相源与投影分离**：文件是权威，SQLite 可删可重建，服务 `--immutable`。前端设计文档对"只读约束的是投影、不是整个应用"的澄清是对的。
2. **契约 fail-closed**：未知键拒绝、重复键拒绝、NaN 拒绝、精确有理数分配、错误带字段路径。
3. **纯函数排程核**：裁剪核与预算切分无 I/O、确定性、五桶会计不变量——这是最容易被替换、也最不需要替换的部分。
4. **"系统给护栏、不给数值"**（阶段②决议）：把可变的决定交给调用方、只校验不变量，这个方向天然有利于可替换。
5. **证据纪律**：溯源到 sha256 + quote_ref、`extracted→reviewed` 只允许 human、变异测试并核对还原哈希、"测试全绿 ≠ 验收"。
6. **写存储的方式**：先写临时 → 重读重校验 → 原子替换 → 提交 manifest；历史记录写一次。

项目原定的 "契约 → 纯函数 → 台账 → 结构化 → 路线 → 投影 → 课表 → 前端" 顺序是合理的，执行也基本守住了。

所有模块与 CLI 只从这里取路径（`--workspace` 参数，默认项目根下这份文件）；删除所有 `Path(__file__).parents[2]` 与 `F:\…` 常量。
**"替换某棵树"就变成：放入新文件 → 通过校验 → 改这里一行 → 重建投影。**

### 5.2 端口清单（每个端口 = 一份规格 + 一组契约测试）

| 端口 | 规格文件（建议） | 现有实现 | 契约测试（替换者必须通过） |
|---|---|---|---|
| 知识树 | `contracts/knowledge_tree.schema.json` | 三科 yaml | 契约加载 + `verify_tree` + 引用门禁 |
| 真题索引 | `contracts/exam_index.schema.json` | 11 份 json | 规格校验 + 题号唯一 + 分值合计规则 |
| 题→知识点权重 | `contracts/topic_weights.schema.json` | `topic_weights.json` | 分布和 = 1 + 参照完整性（→树、→索引） |
| 词汇源 | `contracts/vocabulary.md`（sqlite 视图规格） | sqlite | 存在 `v_top_words` 且列满足规格 |
| 配置 | `contracts/config.schema.json` | fixture yaml | 现有 `test_contracts` |
| 复习项 / 队列 | `contracts/review_item.schema.json` + `ReviewQueueStore` Protocol | `review_shards` | 读写往返一致、原子提交、拒绝坏数据 |
| 复习推进算法 | `ReviewAlgorithm` Protocol | `fixed_bootstrap + sm2_lite` | 纯函数、`due_date > completed_on`、不变量③ |
| 日计划 / 完成事件 / 月结 | `contracts/day_plan…`、`PlanStore` Protocol | `day_plan_store` | 5 条护栏、写一次记录拒绝覆盖 |
| 可用时间 | `contracts/availability.schema.json` | ⬜ | 日期唯一、分钟 ≥ 0 |
| 规划者 AI | `contracts/planner_input…`、`planner_output…` | ⬜ | 输出通过 `day-plan submit` 校验；带 actor 与 input_hash |
| 投影 | `contracts/projection.md`（表与视图） | `ky/projection` | 确定性 + 永不写回 + 表结构符合规格 |
| 前端 | 只依赖"投影规格 + 写入规格" | ⬜ | 写入后重建、页面读到新值 |

做法建议：契约测试写成**参数化**的（`tests/contract/`），对"当前实现"跑一遍；替换者把自己的实现注册进去再跑一遍——**"按 README 替换完仍正常工作"的验收命令就是这组测试**。
