## 0. 审查最终结论

Codex 的最终裁决是**有条件通过**，条件为：修正验收文本里那条被它证伪的全称断言
（"对任意合法比例与预算，精确值与旧浮点值差异 ≤ 1"），并让测试按修正后的契约断言。
Codex 同时明确：**问题在验收要求，不在实现，不应回退到旧 float 乘法**，并接受了
DSH 保留精确实现的决定。

条件已关闭，做法（三项）：

1. **改断言基准**：把"与旧 float 乘积比较"改为"与精确有理乘积比较"——
   即断言 `exact == floor(total × Fraction(str(ratio)))`、`exact <= 真实乘积 < exact + 1`、
   `0 <= exact <= total`。不再把被替换掉的 float 乘法当权威。
2. **收窄兼容性承诺**：与旧 float 完全一致只承诺在**有产品意义的范围**
   （`0.45` / `0.60`，`total = 1..20000`，实测 0 不一致）；已知差异
   （`total=53, ratio=1/53` → 精确值 0、旧值 1）由专门测试**显式断言**，不被宽松容差掩盖。
3. **修掉两处被点名的实现瑕疵**：`_scale_minutes` 的 docstring 原文声称"日常预算下与 float 乘积逐位相同"，
   已被 `1/53` 反例推翻，现已改写为准确表述并写明"不要改回 `int(total * ratio)`"；
   `_proportional_split` 的 `assert` 改为显式 `RuntimeError`（`python -O` 下不会消失，且可诊断）。

**一条贯穿本次交付的教训：替换实现时，"行为不变"必须被验证，不能靠断言。**
5 轮审查里被抓住的三个问题（未知键被静默忽略、大预算超分、精确化改变日常行为），
没有一个是被测试抓到的，全部是被**独立审查 + 变异测试**抓到的。

## 0. 一条被审查纠正的语义决定（值得单独记录）

收尾时 DSH 为了让"极大预算"不再抛出未捕获的 `OverflowError`，把配额计算从
`int(total * ratio)` 改成精确有理数 `floor(total × Fraction(str(ratio)))`。

Codex 随即发现这**不是**完全等价的替换：在 800 万个"比例 × 预算"组合里有 5,658 例不一致，
集中在 `1/53`、`2/53`、`3/53` 这几个无限循环小数的浮点表示上。

DSH 核实后的结论是：**不一致的是旧实现，不是新实现。**

```text
total = 53, ratio = 1/53 存成 float 0.018867924528301886

  文档写下的最短十进制 = 9433962264150943/500000000000000000   < 1/53
  实际存储的二进制值   = 5438308983994561/288230376151711744   < 1/53

  53 × 十进制精确值 = 499999999999999979/500000000000000000 → floor 0
  53 × 二进制精确值 = 288230376151711733/288230376151711744 → floor 0
  int(53 * ratio)   = 1     ← 纯粹是 double 乘法把 53*ratio 向上舍入到 1.0
```

两种"精确"解读都得 **0**，只有浮点乘法得 1。契约写的是 `floor(total × ratio)`，
所以旧值来自浮点舍入误差。DSH 据此**保留精确实现**，并作废了"必须与旧浮点全等"这条要求，
替换为三条更准确的不变量（已由测试固化）：

1. `0.45` 与 `0.60`（本项目真实使用的比例）在 `total = 1..20000` 与旧表达式**完全一致**；
2. 对任意合法比例与预算，差异**不超过 1 分钟**，且精确结果**绝不超过**文档所写比例的真实乘积；
3. 已知差异（`total=53, ratio=1/53` → 0）必须被测试**显式断言**，不得被"允许 1 分钟偏差"掩盖。

**由此确立一条工程规则：替换实现时，"行为不变"必须被验证，不能靠断言。**
这条不一致正是被审查抓出来的，而不是被测试抓出来的。

## 1. 为什么第一阶段做这个

需求文档 §18 要求"先整理近十年考研资料"。两个模型**独立**得出同一结论：这个顺序是错的。

**复习容量在每日 2 小时预算下会数学上崩掉**，而这个结论在拿到任何真题之前就能用纯算术证明：

- 到 2028 年 12 月初约 **811 天**，`811 × 120 = 97,320 分钟` 是"不缺勤、不减量"的理论上限；
- 稳态下每天新增 `n` 个复习单元、每次 `r` 分钟，按 5 次复习，约 30 天后**每日到期复习就需 `5nr` 分钟**；
- 取 `n = 5, r = 5`（已经很保守）就是 **125 分钟 > 全天 120 分钟**；
- Codex 的敏感性与 Claude 的具体代入（约 1200–1600 个知识点 / 510 个有效日 → 稳态 12.5 条/天
  × 5–15 分钟 = 62.5–187.5 分钟，另加单词通道 50–200 分钟）指向同一结论：
  **中位合计约 250 分钟/天，是预算的 2 倍以上**。

所以第一步不是抓资料，而是把这个最容易被现实击穿的假设做成**可执行、可验证、可重放**的代码。

## 3. 算法语义（实现后的事实）

### 3.1 预算切分（`budget.py`）
1. 先保证每个 active 科目的 `min_daily_minutes` 保底；
2. 余量按权重用**最大余数法**分配，结果精确加总到预算，不丢分钟；
3. 权重先归一化，因此容差内被接受的权重（如和 = 1.0000009）也不会超分。

> 政策后果要说清：保底优先意味着预算小的时候，有保底的科目会拿到**高于其名义权重**的份额。
> 例如 66 分钟新学预算、英语保底 15 分钟时，实际是 20/25/21 而不是 26/14/26。

### 3.2 复习裁剪（`review_clip.py`）
排序键（全序，最后一级 `review_id` 保证确定性）：
```text
(-逾期天数, -延期次数, -遗忘次数, -科目落后率, due_date, 类型优先级, 自评, review_id)
```
裁剪规则：
- `used + cost ≤ 软配额` → 任何到期项都可入选；
- `软配额 < used + cost ≤ 硬上限` → **只有 urgent 项**可继续占用；
- `used + cost > 硬上限` → 延期；
- `cost > 硬上限` → 进 `unschedulable`（提示拆分），不在 backlog 里永久饥饿。

**延期语义**：被延后的条目 `due_date` **原样保留**，只 `defer_count + 1`。
不静默改期、不写回、不需要额外审计；逾期天数增长本身就会在后续日期抬高它的优先级。

**自评权限**：`self_rating` 只能做全序的**最后一级业务 tie-break**，
不能改 due_date、不能改间隔、不能跳过复习、不能提高质量分。

## 5. 审查过程中真实发生的事（这段比结论重要）

这一轮暴露了"测试全绿 ≠ 验收通过"的完整实例，值得留档：

| 步骤 | 发生了什么 |
|---|---|
| 1 | DSH 写完阶段 1，**49 条测试全绿**，preflight 正常/违规路径都对 |
| 2 | Codex 独立审查 → 裁决 **不通过**，报 4 个 MAJOR：未知键被静默忽略、复习条目未校验科目存在且 active、合法配置在满载日崩溃、`NaN` 绕过全部浮点校验；并点名 **7 条假测试** |
| 3 | Claude 同时做了自审，**看不到 Codex 的报告**（背对背），修的是另外 6 个问题（A1–A6），测试涨到 **56 条且全绿** |
| 4 | DSH 写独立验证脚本复核 → **3/12 通过**，坐实 Codex 的 4 个 MAJOR **一条都没修** |
| 5 | 把 Codex 报告交给 Claude 修复 → **78 条测试全绿**，验证脚本 **13/13 通过** |
| 6 | Codex 现在正在做复审：自写探针 + **变异测试**（把实现故意改坏，确认对应测试真的会红） |

**教训**：56 条全绿的测试没能覆盖 4 个真实缺陷。这直接支持了评审结论里那条要求——
**进入下一阶段的门槛是上一阶段的可复现证据，不是测试通过数。**

## 6. 尚未解决 / 需要你或后续阶段决定

1. **`self_rating` 的字段位置**：现在放在 `ReviewItem` 顶层。每复习一次就会产生一条新的自评记录，
   届时需要决定是覆盖顶层字段还是写入独立的追加式历史（当前实现是覆盖，尚未验证长期是否够用）。
2. **科目落后率窗口**：现在由调用方传入 `seven_day_usage`。7 天窗口是默认值，没有实测依据，
   需要在有真实学习记录后校准。
3. **`urgent` 阈值**：`overdue ≥ 3 天` 或 `defer_count ≥ 2` 是拍的默认值，同样需要真实数据校准。
4. **`preflight` 可以读任意路径**：目前不限制 `--config/--items` 必须在本项目目录内。
   本地单用户场景下不是安全边界，但如果将来接 Web 就必须收紧。**需要你决定是否现在就加路径约束。**
5. **复习容量的具体数字全部未核实**：1200–1600 个知识点、单次 5–15 分钟、510 个有效日
   都是估计值。拿到真实 408 / 数学一大纲后，必须用确定性脚本重新计数校准。
