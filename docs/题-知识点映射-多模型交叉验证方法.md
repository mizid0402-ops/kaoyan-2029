# 题↔知识点映射：置信度加权多模型法（最终版）

> 日期：2026-09-13
> 范围：408（2023–2026）、数学一（2023–2026）、英语一（2024–2026），共 **11 个批次 / 385 道题**
> 编码者：`gpt-5.6-sol`、`gpt-5.6-luna`、`claude-sonnet-5`（三方独立、互不可见）

## 零、这份文档取代了什么

交接文档 §8.2-3 原文：**「题号↔知识点映射必须用户本人录入或复核——这是金标，不可由 AI 生成」**。

**该规则已废弃，理由由用户提出，且无法反驳：**

> 「我现在还没有系统性的学过这些东西，如果你让我每道题都能分析出来他到底考的是哪个知识点，
> 那不就证明我已经学的差不多了吗，我为何还要写这个系统。」

反过来也成立：**零基础的人判断"三个 AI 都拿不准的边界题"，不会比 AI 更准，只会更随机。**
所以"分歧交人工"不是可靠兜底，而是把最难的一部分推给用户。

**改为两条：**

1. **不强行二元归类，改权重占比**——一道综合题本就跨多个知识点，
   压成唯一标签会丢掉复习价值的分布。
2. **分歧不是失败，是信号**——三方不一致自动变成多节点权重，不交人工裁决。

## 一、方法

### 1.1 编码

每个 coder 独立完成：对每道题，**只从该科考纲树的节点表里选节点 id**，
给出 `nodes`（可多个）、`primary_node`、`confidence`（high/medium/low）、`reason`。

**节点表**由该科知识树中 `chapter`/`section`/`item` 三层节点导出（各批次 sha256 已随产出记录）。
**不得自创 id**；找不到对应节点须填 `null` 并标注「疑似考纲外」。

### 1.2 加权聚合

```
每题权重 = 1.0（归一化）
每个 coder 投出的权重 = 置信度权重（high 1.0 / medium 0.6 / low 0.3）
                        ÷ 该 coder 列出的节点数
节点得票 = Σ 各 coder 投给它的权重
```

若三方一致 → 该题权重 1.0 落在单一节点；
若 2:1 分裂 → 该题按 0.67 : 0.33 计入两个节点。
**分歧自动成为"这题跨了两个点"的量化表达。**

### 1.3 汇总粒度

`chapter` 是复习调度的粒度，故主产物是**章节级权重**。
数学一用其自身 `chapter`；英语一树无 chapter 层，退到 `section`。
更正：上述数学一 / 英语一粒度描述与 2026-09-13 产物不符；按决策者
2026-09-25 裁定，汇总粒度以 `contracts/topic_weights.md` 的登记规则为准。

## 二、执行结果

### 2.1 完整性审计（编码者无法造假，由主控复核）

| 检查 | 结果 |
|---|---|
| 批次 × coder 运行数 | **30/30 全部产出 JSON**（另 2024 的 3 份早期运行） |
| `entries` 条数 = 该科题量、题号无缺无重 | **11/11 批次全过** |
| **自创节点 id** | **全部批次 = 0** |
| 声明的节点表 sha256 = 实际文件 | 一致 |

> **一处我自己的错误要记账**：首次分析报出 75 个"INVENTED id"，实为我的分析器
> 漏了 `tasks/` 子目录，导致有效节点集为空、把真实 id 全判为自创。
> **coder 一个节点都没自创。** 这是我本轮第 5 次探针出错
> （前 4 次：漏读第 40 张卡、把 sha256 当内容、英语一 0.5 分判非法、把树的 `detail-*`
> item 误当"注释节点"）。**5 次全是探针错、数据对。**

### 2.2 三方一致率（385 题）

| 判定 | 条数 | 占比 | 含义 |
|---|---:|---:|---|
| **unanimous**（三方同一节点） | **248** | **64%** | 强一致 |
| **same_branch**（同分支不同层级） | 30 | 8% | 强一致 |
| **same_chap**（同章不同节） | 93 | 24% | 权重分散 |
| **SPLIT**（跨章分歧） | 13 | 3% | 权重分散 |
| missing | 1 | 0% | 某 coder 未给 |

**强一致合计 278/385 = 72%。**

### 2.3 共享偏见检验（加第三方 coder 的目的）

两个 Codex 系 coder（sol / luna）的一致，**部分可能源于同源训练而非双方都正确**。
故检验：Codex 两方判为一致的 306 行里，不同家族的第三方是否翻案到**不同章节**。

```
Codex 两方一致的行数          : 306
第三方翻案到「不同章节」的行数 : 1
矛盾率                        : 0%
```

**结论：两方一致没有系统性虚高**，方法可用。

**⚠️ 这个检验的边界（不可忽略）**：0% 只证明"没有**跨章**级虚高"，
**不等于**三方一致的 248 题全对。**同章内的细粒度错位不会被它发现。**
共同偏见的防线是分层的，本检验只挡住粗粒度那层。

### 2.4 一处必须记录的**方法学局限**：树越粗，一致越廉价

| 批次 | 单一节点题数 | 权重分散题数 |
|---|---:|---:|
| cs408 2023/2024/2025/2026 | 23 / 23 / 20 / 22 | 24 / 24 / 27 / 25 |
| math1 2023 / 2025 | 15 / 13 | 7 / 9 |
| **math1 2024 / 2026** | **0 / 0** | 22 / 22 |
| **eng1 2024 / 2025 / 2026** | **0 / 0 / 0** | 52 / 52 / 52 |

**这不是"英语一更难"**，而是**树的可分辨力差异**：
- **cs408 树有 383 个可指派节点**（item 层 243 个），足以区分到细粒度
- **英语一树只有 24 个节点、无 chapter 层**，52 道题只能挤进少数 section
- **数学一树 69 节点**，且存在 `／考试内容` 与 `chapter` 两套并列节点，coder 常两者都列

**含义**：**英语一的"0 单一节点"不代表 52 题都跨点，而代表树没细到能唯一安置。**
其权重因此是"按最细可用粒度归一化"，**不是同一量纲的细粒度归属**。
若要让英语一的权重有意义，**先得把它的树做细**（这是既有交接文档已列为待办的事）。

## 四、与旧方案的对比

| | 旧（单标签 + 人工裁决） | 新（置信度加权） |
|---|---|---|
| 每题产物 | 一个节点 id | **节点/章节权重分布** |
| 三方分歧 | 交人工裁决 | **自动成为多节点权重** |
| 用户负担 | 复核 ~28%（107 题） | **不参与归属判定** |
| 官方标准答案依赖 | 隐含需要（否则无法判对错） | **不需要** |
| 对复刻/回忆来源的适应性 | 差（要求唯一正确归属） | **好**（分歧即信息） |

**用户的负担转移到了更该由人决定的地方**：如"权重低于多少的章节不进复习队列"这类**阈值决策**，
而不是逐题判归属。

## 五、写回状态字段（round 15 写回 / round 18 改名）

round 15 已把本文档描述的权重分布写回 `data/exam_questions/*.json`
（`tools/apply_knowledge_weights.py`），`knowledge_point_status` 取值：

| 取值 | 含义 | 谁产生 |
|---|---|---|
| `not_assigned` | 未赋知识点 | — |
| `assigned_multi_model` | **三个 AI 模型独立给出同一节点**（本文档 §1.2 的单节点分布） | `tools/apply_knowledge_weights.py` |
| `assigned_unreviewed` | 权重分散在多个节点（本文档 §1.2 的分歧分布） | `tools/apply_knowledge_weights.py` |
| `assigned_reviewed` | **人工**对照官方答案书或源转录逐条核实过 | 目前**暂无人使用**——本流程无权写入 |

`assigned_reviewed` 曾在 round 15 里被临时用来表示"三方一致"，round 18 改名为
`assigned_multi_model`，理由：三方一致是**模型间共识**，不是**人工核实**，两者证据强度不同，
沿用 `reviewed` 会让字段名撒谎。`assigned_reviewed` 的语义现在**只留给未来的人工复核**，
`tools/verify_408_index.py` 会拒绝任何带 `knowledge_point_weights`（即本流程产物的指纹）
却标 `assigned_reviewed` 的记录，防止再次张冠李戴。
