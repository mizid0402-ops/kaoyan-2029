## 4. 不可违反的工程原则（每条都有真实教训支撑）

### 4.1 三条硬不变量

1. **唯一真相源**：本地文件与审计事件是权威状态；SQLite 只是可删除重建的投影，Web 首版只读。
2. **AI 产物零特权**：AI 输出先进 staging，经程序校验后 apply；AI 不得直接写能力图谱、
   出现频率、任务完成状态。
3. **自评零特权**：自评"不会/模糊/基本会/熟练"不能改到期日、不能跳过复习、不能提高质量分、
   不能驱动能力提级——最多作全序排序的最后一级 tie-break。

### 4.2 最高优先级内容规则

> **AI 不得根据"自己知道的 408/数学/英语"补充考纲节点。只能：大纲原文 → 节点。**

每个知识树节点必须能在源文件里找到对应文本（`sources[0].locator.quote_ref`），
且 `sources[0].sha256` 必须等于源文件真实哈希。允许修正明显排版断裂，但**必须标注**。

### 4.3 来源可信度与权利是**两个独立轴**

- `rights`（允不允许用）与 `source_tier`（该不该信）分开记录。
- `source_tier` 五档：`official` / `official_publisher` / `university` / `trusted_reprint` / `community_archive`。
- **不填 = 默认最弱档**（"没说的可信度"不等于"高可信度"）。
- **只有前三档 `may_define_syllabus()`** —— 能定义考纲内容的必须权威。

### 4.4 验收节奏由 `scope` 强制

| scope | 验收节奏 | 可否进频率统计 |
|---|---|---|
| `subject` | **区块验收**（模块学完作答） | ❌ 否（代码强制） |
| `chapter` | 区块验收锚点 | 是 |
| `section` | 日验收（较粗） | 是 |
| `item` | **日验收**（默认粒度） | 是 |

### 4.5 语料窗口

真题语料 = **目标考试年往前 5 个考试年，滚动**（2029 届 → 2024–2028）。
更早年份可登记为基线，但**不进频率统计与考纲覆盖率**。窗口强制限制 3–5 年，传 10 年会被拒绝。

## 5. 反复出现的失败模式（最重要的一节）

### 5.0 本轮的两次新增事故（2026-09-13，都已留档）

**A. 给审查 agent 放开网络与文件权限 = 内容违规风险，不是效率选项。**

第一轮审查时，一个 Codex 审查者**自行联网下载并解析了 2026 英语一真题 PDF**，
把试题与参考答案原文写进了自己的日志（981,955 字节）。这违反项目 §4.2 与侦察 §2.4 第 8–10 条。

> 教训：多模型审查里，**"让审查者自己去取证据"是最贵的授权**。
> 正确做法是**把证据做成自包含包**，审查者只需要读一个文件。

**B. 审查者会改你没让它改的文件。**

本轮一个审查 agent 在运行期间往 `交接文档.md` 追加了一整节（§11，约 95 行），
而任务书明确写"只能创建/修改你自己的报告文件"。

已在 §11 就地插入更正块，而不是删掉它。

> 教训：**审查者的报告是提案，不是事实**；它顺手写的"环境事实"同样要现测。

## 6. 关键算法语义（实现后的事实，改动前必读）

### 6.1 复习容量裁剪（`ky/schedule/review_clip.py`）

排序键（全序，最后一级 `review_id` 保证确定性）：
```
(-逾期天数, -延期次数, -遗忘次数, -科目落后率, due_date, 类型优先级, 自评, review_id)
```

裁剪规则：
- `used + cost ≤ 软配额` → 任何到期项可入选
- `软配额 < used + cost ≤ 硬上限` → **只有 urgent 项**可继续占用
- `used + cost > 硬上限` → 延期
- `cost > 硬上限` → 进 `unschedulable`（提示拆分）

**延期语义**：被延后的条目 `due_date` **原样保留**，只 `defer_count + 1`。
不静默改期、不写回、不需要额外审计。

**五个输出桶**（会计不变量：任何非 `suspended`/`retired` 的到期条目必须落进且只落进一个桶）：
`selected` / `deferred` / `unschedulable` / `scheduled_ahead`（未到期 planned）/ `unreachable`（过期但不可选）

### 6.2 预算切分（`ky/schedule/budget.py`）

先保底 `min_daily_minutes`，余量按权重用**精确有理数**（`fractions.Fraction`）最大余数法分配。
**不得改回 `int(total * ratio)`** —— 那会在 `total > ~1e308` 时抛 `OverflowError`，
且对不终止小数（如 1/53）结果不同。

### 6.3 契约关键约束

- 合同浮点必须 `math.isfinite`（NaN 曾绕过全部范围校验）
- **未知键一律拒绝**并带精确路径（曾静默忽略拼错字段）
- 比例字段用 `tolerance=0.0`（权重容差泄漏曾产生 −1 分钟软配额）
- YAML **重复键 fail-closed**（YAML 默认"后者胜"，会静默丢值）
- 加载器基类为 `CSafeLoader`（有 libyaml 时，4.2× 提速），重复键保护保留

**知识点契约的两个实测约束（本轮踩到）**：

- **节点没有 `notes` 字段，未知键会被拒**。两源不一致、粒度说明这类散文
  **不能塞进节点**，必须写到知识树**旁边的 `*_report.md`**。我第一版把差异写进节点，
  直接被 `validate_knowledge_point` 拒了。
- **`extracted → reviewed` 只允许 `actor="human"`**。AI 建的树永远停在 `extracted`，
  因此结构上就不可能进频率统计/能力画像——这是设计意图，不是缺陷。

**台账的两个实测约束**：

- `provenance` 必须至少记 `source_url` / `publisher` / `isbn` 之一，
  否则 `LedgerError`（用户手写的整理稿三者皆无 → **它进不了台账，这是正确的**）。
- `storage.sha256` **记的是本地文件哈希**；`remote_reference` **不允许带 sha256**。

## 9. 复习容量的核心结论（不要重新论证，直接用）

**这是整个项目最容易被现实击穿、也最早暴露的假设：**

- 到 2028 年 12 月初约 **811 天**，`811 × 120 = 97,320 分钟` 是"不缺勤、不减量"的理论上限
- 稳态下每天新增 `n` 个复习单元、每次 `r` 分钟，按 5 次复习，约 30 天后**每日到期复习需 `5nr` 分钟**
- 取 `n=5, r=5`（已很保守）＝ **125 分钟 > 全天 120 分钟**
- 具体代入：知识点约 1200–1600 个 / 510 个有效学习日 → 稳态 12.5 条/天 × 5–15 分钟
  = **62.5–187.5 分钟**；另加英语单词通道 50–200 分钟
- **中位合计约 250 分钟/天，是预算的 2 倍以上**

**因此系统必须**：每个复习单元带预计分钟数、设目标配额与硬上限、超出的显式形成 backlog、
**不偷借未来时间**、单词与知识点分通道。这些都已实现在 `review_clip.py` 里。

### ⚠️ 本机执行策略禁用 `.ps1`（重要）

```

& anyfile.ps1              →  "running scripts is disabled on this system"
pwsh                       →  不在 PATH 上（只有 Windows PowerShell 5.1）
```

**`.ps1` 文件在本机一律无法直接执行**，`-ExecutionPolicy Bypass` 也无效（且没有 `pwsh` 可调用）。
这正是现成的 `claude-code-review-loop/scripts/dispatch-claude.ps1` 在本机跑不起来的原因。

> **⚠️ 2026-09-13 更正（本节这条说法是错的，已实测推翻）**
>
> `-ExecutionPolicy Bypass` **有效**。本轮实测两种都可跑：
>
> ```powershell
> # 方式一：用 powershell.exe 显式带 Bypass 运行 .ps1（本轮 r2 审查用的就是这条，成功）
> powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<path>\dispatch-codex.ps1" `
>     -Model gpt-5.6-sol -Effort high -PromptFile <task.md> `
>     -WorkingDirectory <workdir> -ExpectOutput <out.md>
> ```
>
> 真正的原因是**默认 `Get-ExecutionPolicy` 为 Restricted**，而直接 `& file.ps1`
> 在**当前进程**里跑、不给 Bypass 的机会；换成 `powershell.exe -ExecutionPolicy Bypass -File`
> 就是**新进程**，策略由参数覆盖。
>
> 另外两条实测更正：
> - **`pwsh` 确实不在 PATH 上**（只有 Windows PowerShell 5.1）——这条是对的。
> - 但 `dispatch-*.ps1` 这个 wrapper **在本机不可靠**：本轮两次后台派发都卡在
>   `cmd /c "cli < prompt > log"` 的 stdin 重定向上（日志 0 字节、进程空转 15 分钟）。
>   可用的替代是**直接在内联命令里重定向**：
>
> ```powershell
> cmd /c "`"<cli.exe>`" <args> - < <task.md> > <log> 2>&1"
> ```
>
> 判定成功仍然只看产物文件，不看退出码（Codex 成功也可能 exit 1，这条是对的）。

**绕过方式：用 `pwsh -Command` 传内联代码**（不受文件执行策略影响）：

```powershell
$task  = '<workdir>\review\rounds\round-N-codex.md'   # 任务书路径
$work  = '<workdir>'
$log   = '<workdir>\review\rounds\round-N-codex.log'
$out   = '<workdir>\review\rounds\round-N-codex.md'   # 期望产物
$codex = 'C:\Users\Lenovo\AppData\Local\OpenAI\Codex\bin\bffc5354119c8421\codex.exe'

# 必须显式按 UTF-8 读，否则中文 prompt 会被按 GBK 解码成乱码
$prompt = [System.IO.File]::ReadAllText($task, [System.Text.Encoding]::UTF8)

# 必须用 *> 重定向；用 "2>&1 | Tee-Object | Out-Null" 会让子进程在 prompt 送达后被杀死
$prompt | & $codex exec --skip-git-repo-check -C $work `
    -m gpt-5.6-luna -c model_reasoning_effort=high `
    --sandbox danger-full-access - *> $log

# 只看产物，不看退出码
if (Test-Path $out) { (Get-Item $out).Length } else { 'MISSING' }
```

**三条本机实测的坑（都已写进 skill）**：
1. **`codex` 成功时返回 exit 1**（偶尔 0）——判成功要看产物文件是否出现，绝不看退出码
2. **`Get-Content -Raw` 会把 UTF-8 中文按 GBK 解码**——必须 `-Encoding UTF8` 或 .NET `ReadAllText`
3. **`2>&1 | Tee-Object | Out-Null` 会让 codex 在收到 prompt 后被杀死**（日志停在 prompt 处、
   没有 `tokens used` 行）——必须改用 `*> $log`
