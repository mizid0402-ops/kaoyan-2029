## 三、决策记录（Claude）

### D1 408 生效树 = 403 版 `knowledge_tree.yaml`；410 版登记为"补充视图"

- 我起初选 410 版，依据是 `review/阶段收尾-知识树与真题.md:16` 称其为"多源主表"。gpt-6-sol 反对，理由成立：
  "主表"指**溯源最丰富**，不等于**当年考纲生效范围**；多出的 7 个节点是 `legacy_only_pending`，
  把它们计入"408 有多少点要学"会虚增范围；且更多消费者（索引校验、题目分类、树完整性测试、快照）读 403 版。
- 定稿：工作区配置里 `knowledge_trees.cs408` 指向 403 版（生效范围）；410 版登记为
  `supplementary.cs408_multisource`（附加 2022 来源 + 7 个待定旧节点），投影与 PPT 生产线如需它，必须显式读这个键并如实标注。
- 两份文件都已冻结，本决策**不改任何数据文件**，只改谁读哪一个。
- **连带后果（gpt-6-sol 第 2 轮指出，已核实）**：
  - `knowledge_tree_agreement.yaml`（410 行）是**对 410 版的注记**：380 个共同节点的附表 `source_count` 与 403 版实际来源数不同。
    所以附表必须和 410 版一起绑定为补充端口，**不能把投影的树路径换成 403 而保留原样拼接附表**；若展示，字段须标明"跨年来源支持"。
  - 投影 `knowledge_points` 以 `knowledge_point_id` 为单列主键 → 该表只收 403 生效点；补充树另设表/视图。
    `v_knowledge_points_by_subject`、`projection_meta.inputs` 的计数与哈希随之调整；新增独立断言：cs408 生效点数 = 403、7 个 legacy ID 不在生效表、补充数据可追溯。

## 四、组织原则：按模块区分优先

每个工作包（WP）**只落在一个模块/端口上**，以同一套四件套收尾：

1. **规格**：`contracts/<port>.md`（Markdown + 示例文件；JSON Schema 在该端口稳定后补）
2. **实现改动**：只动本模块，跨模块只通过工作区配置或规格
3. **契约测试**：`tests/contract/test_<port>.py`，参数化，可对替换实现重跑
4. **替换说明**：README 模块表对应一行（审查报告 §5.3 模板）

## 七、用户决议（2026-09-25）

### D3 审查项 B1：保留硬不变量③，复习完成只认有锚点的核对结果（用户选 a）

- `ReviewCompletion` 的输入从"0–5 自评分"改为**核对结果**：
  `check`（`past_question` 真题 / `exercise` 练习题 / `recall_vs_notes` 默写后对照）+ `outcome`（`correct` / `partial` / `incorrect`），
  可选 `question_ref`（真题题号，`topic_weights` 已有题→知识点映射）。
- 系统用**固定映射**把 `outcome` 换算成推进用的质量分，再走原有阶梯与 SM-2；映射表是 `ReviewAlgorithm` 端口的一部分，可替换。
- 只有自评、没有 `check` 的完成：记为"做过"，**不推进阶梯、不改 ease**，按当前间隔再排一次。
- 自评（四档）照旧可记，只做裁剪核排序的最后一级 tie-break。
- **细节默认取严格版**：自评"不会"也不缩短间隔（不变量③原文不动）。若以后要允许"自评只能缩短、不能延长"，只改这一条规则并记决议。
- 历史数据：已有完成事件里的 `quality` 按"无核对的自评"处理，不追溯改写（写一次记录不可改）；新旧格式由 `schema_version` 区分。

### D6 多学科、多方向（用户 2026-09-25 提出）

用户希望项目不止服务 408，也能用于数学专业、农学等方向的考研；用户判断"只需要改数据库接收数据"。核查结论：**排程核心基本对，数据侧不止"接收"一处**。

- **已经与科目无关、不用改的**：预算切分、复习裁剪、复习推进、日计划 / 完成事件 / 月结存储、状态快照、工作区注册表。`ky/` 里科目字面量只剩 2 处：台账白名单 `ky/ledger/material.py:105`、投影 cs408 分域特判。
- **要改的（数据模型，不只是接收）**：
  1. **科目是代码常量**：台账 `SUBJECT_IDS`、`tools/verify_tree.py` 只认三科的章节编号规则（`SUPPORTED_ROOT_SHAPES`）。→ 科目档案进注册表（ID、名称、树的层级 / 编号规则、是否启用英语词汇通道等）。
  2. **真题索引没有"出题单位"维度**：统考（408、数学一、农学 314/315 等）够用，但数学专业的专业课（数学分析、高等代数）多为**各校自命题**，同一科目不同学校卷子不同。→ 索引加 `paper_source`（`national` / 某校代码），卷面形状按（科目, 年份, 出题单位）登记为数据。
  3. **知识树来源假设"官方考纲"**：自命题常无官方大纲，来源是学校发布的考试大纲或指定教材目录。台账已有 `university` 来源档位，契约基本能接；需在树规格里写明允许的来源类型。
  4. **英语词汇通道只对英语科目有意义**：保持为可选模块（英语一 / 英语二都能用），由科目档案决定是否启用。
- **不需要通用化的**：`tools/build_408_*`、`build_math1_tree.py` 这类采集脚本本来就是**科目专用适配器**。新方向写自己的适配器，或直接按端口规格人工 / AI 产出数据（AI 产出按硬不变量②先进 staging）。
