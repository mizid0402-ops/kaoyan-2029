# 任务：用**英文**再审一遍 GitHub —— 补中文检索的假阴性

## 为什么要再用英文搜一遍

上一轮（`report-github-survey.md`）的检索者**自己发现了方法论缺陷并如实报告**：

> GitHub 仓库搜索 API 对**多个中文关键词做 AND 组合时极易返回 0**
> （只索引 name/description/topics/README 的浅层匹配，长尾中文短语很难命中）。
> 这意味着"没找到"里有一部分可能是**关键词覆盖不足导致的假阴性**，不完全等于"真的不存在"。

**本轮就是用英文、拼音、以及不同的命名习惯再搜一遍，去补这个洞。**

## 目标是找什么（按阶段，与上轮相同）

| 阶段 | 找什么 |
|---|---|
| ① 知识树 | **408 / 数学一 / 英语一 考纲的结构化数据**（条目/树/JSON/YAML）、历年真题结构化、多源合并加权实现 |
| ② 计划与调度 | 间隔重复引擎（FSRS 各语言实现、SM-2 类）、长期计划生成、队列调度/容量规划/积压处理 |
| ③ 本机只读 Web | 本机/单文件优先的 Web 方案、从 SQLite 生成只读展示、Markdown/YAML → 静态站 |
| ④ 课表协同 | 课表解析（icalendar/.ics/国内教务导出）、带约束排程、临时覆盖模式 |
| ⑤ 可视化 | 学习进度/雷达图/目标差距、课表周视图/甘特图 |

**阶段①的数据仍是最高优先级**——项目瓶颈是**来源不够**（加权合并需要 ≥2 份独立来源），
找到一份独立的结构化考纲，比找到合并库更有价值。

## 英文检索的方向建议

- **关键词**（不要只用一个词，要组合）：
  `China postgraduate entrance exam syllabus`、
  `kaoyan`（拼音，GitHub 上很常见）、`Postgraduate Entrance Examination`、
  `Chinese graduate entrance exam 408`、`computer science postgraduate exam China`、
  `National Entrance Test`、`NETEM`（全国硕士研究生入学考试英文缩写）、
  `exam syllabus dataset`、`curriculum knowledge graph`
- **命名习惯**：GitHub 上此类项目常用 `-dataset`、`-notes`、`-papers`、`-syllabus`、
  `awesome-`、`-json`、`-scraper`、`knowledge-graph`、`-ontology` 等后缀，试试组合
- **topic 检索**：`topic:kaoyan`、`topic:chinese-exam`、`topic:study-notes`、
  `topic:spaced-repetition`、`topic:exam-prep`
- **中文单关键词**（上轮发现单个关键词命中率明显更高，不要做 AND 组合）：
  `考研`、`考纲`、`大纲`、`408`、`数学一`、`英语一`、`真题`
- **也可以查**：GitHub 上已有的 **Anki 牌组**（`.apkg` 或 `anki` 类仓库）、
  **Obsidian 笔记本**（`obsidian-vault` 考研）、**Notion 导出**
  —— 这些里可能藏着已结构化的考纲或考点
- **不要只用一处搜索**：GitHub 网页搜索、API、以及必要时 Google 的 `site:github.com` 都可以用

## 硬性要求（与上轮一致）

### 1. 每条候选给可核验事实，不要只转述 README

- repo 全名、URL、**star 数、最近提交时间、许可**
- **实际下载**了哪些文件、字节数、**SHA-256（现算）**
- 若声称有结构化数据，**抽样核对**：**只列字段名与条目数**
- 活跃度：最近提交距今多久、是否 archive、issue 是否无人理

### 2. 按三条互不推导的轴分别回答

① **权威性**——**只用于"能否定义考纲"这一件事**
② **准确性**——必须可交叉验证（能算出重合率/一致率这样的数字）
③ **可传播性**——能否落盘 / 再分发，分开答

**不要因为"非官方"就把东西判死。** 非官方能用就用，如实标等级。
**权利不明标 `unknown`，但不因此否掉**——可用"仅本地自用"落地。

### 3. 区分**数据 / 库轮子 / 参考实现**三类，不要混

### 4. 找不到就说找不到

**绝不用模型自己的知识"生成"考纲或真题数据冒充检索结果。**
一条诚实的"没找到"，比一份编出来的结构化考纲有价值得多。

### 5. 不要抄录受版权保护的正文

报告里**只列**：repo 名、字段名、条目数、许可、结构描述。
**不要抄**：考纲正文段落、题干原文、例句、教辅讲解、词表释义文本。

### 6. 本轮要额外做一件事：**说明假阴性问题改善了多少**

对比上轮，**用英文/拼音/topic 检索是否找到了上轮中文检索漏掉的仓库**？
列出来。如果仍然没找到，就说明"英文路径也没补上"，这也是有用结论。
