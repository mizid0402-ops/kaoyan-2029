## 规则 1：`topic_weight` 的汇总

- 逐题分布：三个编码者各自对该题列出的每个节点投 `置信度权重 ÷ 该编码者列出的节点数`（`nodes` 为空的条目不投票），
  按题归一化到 1.0；`per_question` 存的是**舍入到 3 位小数**的分布（你已复现 432/432）。
- `topic_weight`：对**未舍入**的逐题分布求和，每个节点先按该科的上卷规则换成汇总键：
  - cs408：上卷到它所在的 **chapter**（树里 scope 为 `chapter` 的祖先；用知识树端口给出的层级关系求祖先，不要用字符串切 ID——`AGENTS.md`"不从文本倒推结构"。
    若知识树端口没有给出父子关系，先在报告里说明树里是怎么表达层级的，再选最直接的端口字段；实在只能按 ID 前缀，停下来问）。
  - math1、eng1：**不上卷**，按编码的节点原样汇总。
- 上卷规则是数据，不是代码分支：批次清单顶层按科目登记 `topic_rollup: {cs408: chapter, math1: none, eng1: none}`，取值只有 `chapter` / `none`，未知值报错；清单里出现的科目都必须登记。
- 规格 `contracts/topic_weights.md` 写明以上规则，并注明：方法文档 §1.3 对数学一 / 英语一粒度的描述与 2026-09-13 的产物不符，以产物为准（决策者 2026-09-25 裁定）。
  同时在 `docs/题-知识点映射-多模型交叉验证方法.md` §1.3 加一句更正，指向规格。
- 浮点求和顺序：决策者的探针按"清单批次顺序 → 编码者产出里的题号出现顺序 → 节点出现顺序"累加即得到逐位相等。复现测试要求**逐位相等**，不要用容差掩盖顺序差异。
