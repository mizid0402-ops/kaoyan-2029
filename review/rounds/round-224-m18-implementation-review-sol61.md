## 一、必须改

### R1：周网格与同一周的实际课程、分钟数不一致

位置：`ky/__main__.py:1682`、`ky/__main__.py:1702`。

合成输入：登记学校 `demo`，只有第 1 节 `09:00–10:00`，`blocks: [[1]]`。个人课表的规则为学习窗 `08:00–12:00`、缓冲 0、最短空档 0、每大节扣 30、上限 120；学期 `demo-term` 从星期一 `2025-09-01` 开始，共两周。课程和例外如下：

```yaml
courses:
  - {name: A, weekday: 1, periods: "1", weeks: "1"}
  - {name: B, weekday: 3, periods: "1", weeks: "2"}
exceptions:
  - {date: 2025-09-01, kind: no_class}
  - {date: 2025-09-02, kind: follow, follow: 2025-09-10}
```

在合成工作区登记这些文件后，复现命令：

```text
py -3.12 -m ky timetable show --week 1 --workspace <合成工作区>/kaoyan.workspace.yaml --config tests/fixtures/config/config-minimal.yaml
py -3.12 -m ky timetable show --date 2025-09-01 --workspace <合成工作区>/kaoyan.workspace.yaml --config tests/fixtures/config/config-minimal.yaml
py -3.12 -m ky timetable show --date 2025-09-02 --workspace <合成工作区>/kaoyan.workspace.yaml --config tests/fixtures/config/config-minimal.yaml
```

实际周网格的第 1 节显示“周一 A、周二 -”，分钟行却为 `120 90 120 120 120 120 120`。日期解析的实际课程是周一无课、周二 B。我用相同合成对象直接调用当前周显示函数和 `calendar.day`，已复现这组差异；CLI 解析和基础展示另有现有用例验证。

应有结果：周一为空，周二显示 B，分钟行保持不变。网格的每一列应使用该列实际日期的 `DaySchedule.classes`，由 M18 统一解释 `no_class` 和跨周 `follow`；CLI 不再另外实现原始课程匹配。

**裁定：必须改。** 普通节假日、调休都会触发，用户按周网格安排活动会看到错误课程。当前 `--week` 展示具体周次，且附同周实际预算，没有“原始模板”语义。仅增加一句“分钟应用例外”不能让错误课程成为正确的周课表。修改后补覆盖这两个例外的最小 CLI 用例即可。

### R2：零阈值时把空区间作为空闲时段返回

位置：`ky/timetable/calendar.py:92` 的 `_free_segments`。

合成输入：同样的学校第 1 节 `09:00–10:00`；一周学期从 `2025-09-01` 开始，周一 A、第 1 节、周次 `1`，无例外。学习窗改为 `09:00–10:00`，缓冲、最短空档、扣减均为 0，上限 120。所有字段都符合规格。

复现命令：

```text
py -3.12 -m ky timetable show --date 2025-09-01 --workspace <合成工作区>/kaoyan.workspace.yaml --config tests/fixtures/config/config-minimal.yaml
```

当前核心实际返回：

```text
free_segments = (("09:00", "09:00"), ("10:00", "10:00"))
free_minutes = 0
minutes = 0
```

应有结果：`free_segments = ()`，其余两个数仍为 0。整段学习窗都被占用，窗口两端没有非空的剩余区间。

原因是前段和尾段都只比较 `gap >= min_gap_minutes`；阈值为 0 时，空区间也通过。应先要求区间长度为正，再检查最短空档阈值；正长度恰好等于阈值仍须保留。

**裁定：必须改。** 这不是非法输入，也不要求把合法的零阈值禁掉。§4 第 5 条定义的是学习窗减去占用后的空闲段，空区间不是一个剩余时段。日展示直接暴露这些错误段，未来消费者也会收到它们。补一个完全占满窗口的合成核心用例即可。

## 五、建议改

### S1：让基线对照明确断言命令成功

当前 compare_runs 只比较两边相等，没有断言预期成功的两边均为 0。共同 fixture 退化后，两边相同失败也可能绿灯。可使用其返回 ProcessResult 增加成功断言。当前对照通过，没有据此认定产品已经失败。

### S2：补齐空区间的公共参数校验

`TimetableCalendar.minutes_between(d, d, "bad")` 当前直接返回空只读映射；非空区间才通过 day 校验基数。同样的参数合法性不应随区间是否为空变化。建议在进入循环前调用基数校验；本轮已直接复现。不把没有 CLI 触发链的非法参数调用扩成业务返工问题。

### S3：本地错误包装与文档收口

- `_parse_local_path` / `_parse_local_mapping` / `_read_local_overlay` 用 `str(exc).split(": ", 1)` 提取文案，虽然没有按文案分支，仍依赖错误格式。以后可由公开错误属性统一包装；不用为此扩大本包重构。
- `docs/模块地图.md:47`、`:74` 仍将 M18 记为未开始。T1/T2 明确没有让实现者修改地图，决策者提交收口时应按 AGENTS.md 的新组件登记规则补上 M18 接口、规格、测试入口。
- 第 219 轮实现报告还保留旧的配置参数/可选基数描述，应追加“已被当前接口替换”的处理说明，保留历史记录；当前实际接口符合最新版规格。
- M8 模块头公开接口列表可补 `daily_base_minutes`，与 __all__ 和新调用端口一致。
