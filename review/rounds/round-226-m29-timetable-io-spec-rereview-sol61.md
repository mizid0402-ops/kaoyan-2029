## 二、必须改

### N1：工作区外不一定在本 Git 仓库外

涉及 §1，承接上轮 R1。

**具体设置**：一个 Git 仓库根为 `<repo>`，选定注册表位于 `<repo>/work/kaoyan.workspace.yaml`，因此 Workspace.root 为 `<repo>/work`。导出目标为 `<repo>/exports/demo.ics`，该目录未忽略。运行：

```text
ky timetable export-ics --from 2025-09-01 --to 2025-09-08 --config C --out <repo>/exports/demo.ics
```

**草案结果**：目标在工作区根外，按第一条直接允许；但它仍是本 Git 仓库里的普通提交候选文件。

**应有结果**：判断本仓库隔离时使用包含该工作区的 Git 工作树边界；上述目标必须经过 ignore/未跟踪检查，不满足则写前拒绝。只有确实在该 Git 工作树之外的目标，才可按已选“工作区外允许”的意图直接允许。不要求扫描其他仓库。

同时明确 Git 判定的三种状态：找到所属工作树、确认非 Git 工作区、Git 不可调用或查询失败。不能把 `ls-files` 的任意失败都当成“未跟踪”，也不能在 Git 不可用时把未知的仓库边界当成外部目标。无 Git 的解压工作区要允许还是拒绝工作区内写入，应显式选择；按当前 check-ignore 必须成功的字面规则会拒绝，不应由实现者另加隐式回退。

原来“已跟踪文件拒绝”的要求正确，应保留。临时文件和备份各自也要满足隔离，不能只检查最终导出目标。

### N2：周次原表达式已经被现有 M18 模型丢弃

涉及 §2、§3、§5 的规范比较，承接上轮 R2。

**具体输入**：三个其余字段完全相同的合成学期，课程周次分别写为 `1-3`、`1,2,3`、`1-3周`，总周数均为 3。

**已确认代码事实**：当前 `Course.weeks` 只保存 `frozenset[int]`。三种写法加载后均为 `{1,2,3}`，没有原表达式字段。

**草案结果**：§2 要 `semester_to_mapping(semester)`、`timetable_to_mapping(timetable)` 将 weeks “按原表达式”输出；它们从参数中无法分辨上述原文。§3 又要求升序合并连续周的唯一写法。两项不能同时成立，apply 的“规范映射完全相同”也因而没有唯一含义。

**应有结果**：从有效周集合统一输出 `1-3`，单双周集合也输出同一升序规范列表；明确不保留原表达式写法，只保留周集合语义。这样三者应判为同一规范学期，可走“已应用”。原始注释/文本已经通过旧字节备份保留，不需要为重写引入额外原文字段。

课程顺序和例外顺序也应划清：哪些列表保留 M18 的文件顺序，哪些只在 M29 导入/哈希时规范排序。不能让通用 M18 serializer 无条件排序，改变未涉及学期的 `DaySchedule.classes` 展示顺序，又声称现有行为不变。§3 的“exceptions 为空”应明确仅指自动 ICS 导入；restage 必须保留用户添加且合法的例外。

### N3：有限域必须按目标本地日期定义，不能在原始日期上先拒绝

涉及 §4 第 3、4、6、8 条。

**具体 ICS**：

```ics
BEGIN:VEVENT
UID:demo-local-boundary
DTSTAMP:20250101T000000Z
DTSTART:20250831T233000Z
DTEND:20250901T003000Z
SUMMARY:A
END:VEVENT
```

参数为 `--school demo --label term-a --week1 2025-09-01 --weeks 1 --timezone Asia/Tokyo`。合成学校第 1 节为 `08:30–09:30`。

**草案的二义结果**：第 3 步在原始时间域展开并对单次事件检查 `[week1, week1+7N)`，直接用原始 UTC 日期/午夜边界会因 08-31 在域外而拒绝；第 6、8 步按目标本地日期处理，应得到 09-01 第 1 周、周一第 1 节，接受。这也是 §8 继承的上轮时区边界用例之一。

**应有结果**：目标本地日期为 09-01，接受。必须说明 week1/N 表示目标墙上时间的学期日期；展开时将这个本地区间边界投影到每个主事件的原始时间域，不能拿同名 UTC 午夜直接当界限。浮动事件仍按自己的墙上时间。有限展开可以提前做，但不能提前用错误的日期域决定课程是否越界。

覆盖后也需再次检查实际出现：主事件原日 09-07 在一周域内，覆盖移动至 09-08 后，应明确越界拒绝；不能依据“原实例展开已在域内”就宣称移动后的出现也已在域内。反向移入的原实例是否允许，应和有限规则的原域策略一并钉住。

全天、真正缺结束时间等会被 notes 跳过的事件，也要说明是否参与严格域外拒绝；否则先做第 3 步检查会让本应跳过的普通全天事项使整次导入失败。本条要求统一先后口径，不要求扩展 RRULE 支持范围。

### N4：整表校验职责不完整，“已应用”提前返回还绕过引用校验

涉及 §2、§4.11、§5.3–4，承接上轮 R7。

**反例一：候选整表重叠。** 旧学期 A 从 `2025-09-01` 开始两周；新学期 B 从 `2025-09-08` 开始两周，label 不同，学校和节次都有效。

**草案结果**：§2 对 build_calendar 只承诺引用校验（学校/节次）；按这份接口说明，两学期均可通过。§5.4 却要求同一入口检查整表学期不重叠并拒绝。后面的“再解析确认等价”是否通过 M18 完整校验，也没有具体公开调用口径。两处职责不一致。

**应有结果**：apply 明确拒绝重叠，在备份及主文件写入前完成。指定哪个公开入口负责完整 Timetable 不变量（含 labels、区间、rules）以及引用校验；build_calendar 可以承担这项职责，或另给整表公开校验口，但不能只复制私有 `_validate_semesters`。

§4.11 的只含 B 的临时对象**可以**通过导入校验：暂存导入只验证候选学期自身，不必与当前学期区间兼容；与旧表合并的冲突留到 apply。这里应明确区别两个校验范围，而不是让 import 隐式决定未来 apply 方式。

**反例二：已应用但引用文件缺失。** 现有学期与暂存学期规范映射完全相同，学校仍登记，但其档案在拷贝工作区时遗漏。

**草案结果**：§5.3 直接打印“已应用”、退出 0，跳过第 4 步；加 `--replace` 也一样。一般 apply 则应因已登记文件缺失 fail-closed。

**应有结果**：学校引用等必需校验在成功返回之前完成；缺失返回契约错误且不写。确认有效且相同才 no-op。`--replace` 是允许不同内容替换的权限，不能迫使相同有效内容再写备份；同内容、带或不带该选项都保持 no-op，这个方向正确。

**无当前个人课表分支**也应给出明确的公开校验路径：§4.11 要检查学校节次但不构造日历，§2 却只有 build_calendar 承担引用检查。应定义无需 rules 的单学期引用校验口，或明确已有对回节次检查已经提供哪些保证、后续通过哪些公开数据完成校验。不能让 M29 为这个分支复制 M18 引用规则。若没有当前 rules，预览只显示课程网格、没有预算分钟也应写明。

### N5：大节是编号划分，不保证大节内部没有长空档

涉及 §6，承接上轮 R8。

**具体输入**：合成学校两节分别 `09:00–10:00`、`13:00–14:00`，`blocks: [[1,2]]`；学期内周一 A 占 `1-2` 节。学习窗 `08:00–16:00`，缓冲、最短空档、扣减均为 0，上限 480。

这个学校档案符合 M18 §2：大节内要求编号相邻，明确**不要求时刻无间隙**。大节是用户给定的精力扣减划分，不能从它推导午休必定跨大节。

**草案结果**：同一大节合并成 OPAQUE 课程事件 `09:00–14:00`；同时导出 M18 给出的透明可学习窗口 `10:00–13:00`。三小时空档仍在忙碌课内，上轮问题没有在所有合法学校数据上消除。

**应有结果**：至少在此输入上输出 `09:00–10:00`、`13:00–14:00` 两段课程事件，空闲窗口不变。可以保留“先按大节分组”的展示原则，但还必须按实际时间间隙切段；或者明确哪些短间隙允许桥接，且不能覆盖 M18 返回的可学习空档。

不应反过来新增“所有学校的大节必须时间连续”的硬校验，也不应从 M18 删除该空档。常见大节间午休已修好，但数据驱动的学校接入仍需此补充。

## 三、建议补清

### S1：restage 的比较基准与同哈希编辑

restage 读取的是**已被用户编辑的 FILE**；旧文件名中的摘要不能恢复编辑前的学期。现在“打印新旧文件名与学期差异”未指定比较对象。

建议明确比较“编辑后的规范学期与当前已生效同 label 学期”；未生效时打印新增摘要。若要比较编辑前导入快照，就需要保留可读取的原快照，不能凭短摘要反推。此项可在实现任务书钉住，不要求新增恢复日志。

另一个普通场景是只改 notes、缩进或等价周次写法：规范哈希不变，restage 目标可能就是输入文件本身，通用“同名但字节不同拒绝”不能无条件套用。明确已有哈希有效时直接校验并返回原文件、无需重新发布，或另选明确的版本规则；不能静默覆盖人工文件。

### S2：M18 新入口保持已有加载证据

当前正式加载器除了日结果，还保证学校/课表只读一次、sources 使用解析字节的原始摘要、缺失引用的字段路径。新 build_calendar 是纯对象入口，load_referenced_schools 只返回档案映射；应规定纯对象日历的 sources 口径，正式文件日历仍保留现有摘要和错误路径。

不要求所有学校对象增加原文缓存。M18 内部可共用带摘要的加载辅助，公开纯构造入口则使用空 sources 或明确传入来源映射；不能为了补摘要再读同一源文件一次。验收“结果一致”应同时核对 sources 和约定错误路径，不能只看 minutes。

序列化往返也应明确保持课程文件顺序、rules 值及合法例外语义；新入口/public 类型从包入口导出，M29 不 import `_models` 等私有实现。

### S3：UID 的 index 与空选择

- UID 加 kind、结构化哈希、重复区分和完整排序，方向正确。建议 index 定义为相同事件身份组内的稳定序号，而非所有已筛选事件的全局序号；这样同一课程不会因 `--classes-only` 或导出区间前面多一条学习窗口而改变 UID。非重复默认 0，完全相同的重复按稳定顺序编号即可。
- §6 的“空覆盖”指范围内没有任何 M18 覆盖日，拒绝合理。**有覆盖但选中事件为空**是另一状态：例如 no_class 日使用 classes-only，或全窗占用日使用 free-only。建议明确写合法空 VCALENDAR 并退出 0；若选择拒绝，也应另列条件，不要把它误称为“课表不覆盖”。
- 固定主版本不等于所有 minor 版本导出字节必然相同；可要求同一依赖环境同输入确定，依赖升级时核对字节。无需把跨版本字节稳定性当作 icalendar 自动保证。

### S4：重复实例结束时间及异常处理

固定处理顺序已改正取消覆盖先于缺结束过滤的问题。实现任务书宜明确：重复实例的 DTEND 根据主事件时长落到每个实例，不能每次照抄首日 DTEND；覆盖若不能确定结束时刻则按当前 notes 规则处理。主事件 STATUS:CANCELLED、DTEND 与 DURATION 同时存在、起止类型不匹配，也应有校验结果。不要自行猜测或自动修复明显不一致的事件。

## 四、不改与已采纳项

- **不撤回 PDF 分包**：保留独立后续任务和验收，不把它算作当前 ICS 实现的阻塞，也不记成整个路线完成。
- **不恢复无限展开**：无终止 WEEKLY 必须给 N，明确 notes；空导入拒绝能避免误用空学期替换原课表。
- **不扩大覆盖支持**：拒绝 RANGE、孤立覆盖、同实例多覆盖及 EXDATE/覆盖冲突可作为 v1 的明确边界，不必实现完整日历同步。
- **不改备份/替换顺序**：旧字节先完整发布备份，再 replace 主文件；中断前后可重跑，没有必要加两文件回滚事务或 applied 清单。
- **不强制 replace 再写相同内容**：内容有效且规范相同返回已应用是正确幂等方向；只需 N2/N4 定义好比较与校验。
- **不改透明学习窗口**：窗口不是已安排任务，TRANSPARENT 正确；free_segments 不按参考总分钟裁短。
- **不取消浮动时间与 out 必填**：它们是已标明的拟定项，适合本地导出；不引入在线服务、账号密码或自动覆盖。
- **不把普通重复事件去重隐藏掉**：同课程身份同周重复仍明确拒绝；M18 允许的不同课程冲突可以保留并展示。
