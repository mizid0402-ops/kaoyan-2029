# 任务：GitHub 检索 —— 为项目的**后续各阶段**找现成的数据与轮子

## 目的

用户明确要求：**查 GitHub 是为下一步做准备**，范围不限于当前建树，要覆盖计划中的后续阶段
（建树 → 学习计划/复习调度 → 本机只读 Web → 课表协同 → 可视化）。

**目标是少做工作**：能直接拿来用的、或改一改能加进来的，都算收获。

## 项目的阶段顺序（顺序不可跳）

```
① 知识树按权重重构（多源加权合并）    ← 当前正要做的
② 24 个月阶段与容量路线 + 月度闭环
③ 本机只读 Web 投影（SQLite 可重建投影）
④ 课表协同（叠加上限：临时调课、考试周、假期、实习）
⑤ 可视化：课程表 / 学习进度 / 能力画像 / 目标差距
```

**贯穿约束（来自项目既定决策，不要建议违反它们的方案）**：

- **本机单用户、文件为准**（B5）；Web 是**只读投影**，SQLite **可重建**
- 预算固定 **120 分钟/天**；四科占比 数学一 40% / 英语一 20% / 408 40% / 政治未激活（B8）
- **AI 生成题永进不了**频率统计与验收（B10）；政治 12 个月前置、只读 Web（B11）
- 复习调度已有一个**确定性排序核**（全序键：`-逾期天数, -延期次数, -遗忘次数, -科目落后率, due_date, 类型优先级, 自评, review_id`）
- 权利体系：`source_tier`（信任）+ `rights`（许可）**两条独立轴**；
  **判据已修正为三条互不推导的轴**：①权威性（**只用于"能否定义考纲"**）②准确性（必须可交叉验证）③可传播性（能否落盘/再分发）
  —— **不要因为"非官方"就把东西判死**；非官方能用就用，如实标等级即可

## 按阶段分组，你要找什么

### 阶段 ①：知识树（数据，优先级最高）

- **408 / 数学一 / 英语一 考纲的结构化数据**：有没有人已经把考纲抽成条目/树/JSON/YAML
- **历年真题的结构化数据**：题号、考点标注、答案、词频
- **多源合并/共识加权**的实现（把多份不一致的清单合成一份带权重的）

> **背景**：项目现在的瓶颈**不是算法，是来源不够**——
> 408 只有 1 份第三方完整正文、数学一 1 份转录、英语一 1 份目录。
> **加权合并需要 2 份以上独立来源才有意义。**
> 所以**找到一份独立的结构化考纲，比找到一个合并库更有价值**。

### 阶段 ②：学习计划与复习调度

- **间隔重复（SRS）引擎**：FSRS（Free Spaced Repetition Scheduler）及其各语言实现、
  或 SM-2 类算法库
- **考研/应试类的长期计划生成**（若有）
- **队列调度、容量规划、超期/积压处理**的通用库

> 注意：项目已有自己的确定性排序核，**引入 SRS 是替换还是叠加，需要评估**——不要默认替换。

### 阶段 ③：本机只读 Web 投影

- **单文件/本机优先**的 Web 框架或模板（Python 侧优先，项目是 Python）
- **从 SQLite 生成只读展示**的现成方案
- **Markdown/YAML → 静态站**的生成器（若合适）

### 阶段 ④：课表协同

- **课表/日历文件解析**：`icalendar` / `.ics` / 国内高校教务系统导出格式
- **带约束的排程**：把固定不可用时段（上课）+ 可变任务（复习）排进每天的可用窗口
- **调课/考试周/假期/实习**这类**临时覆盖**的处理模式

### 阶段 ⑤：可视化

- **学习进度 / 能力雷达图 / 目标差距**的现成组件（Python 优先；若为前端库也可）
- **课表可视化**（周视图、甘特图类）
- 项目要求政治科目用**柱状图**（B11）

## 硬性要求

### 1. 每条候选都要给可核验的事实，不要只转述 README

- repo 全名、URL、**star 数、最近提交时间、许可（License）**
- **实际下载**了哪些文件、字节数、**SHA-256（现算）**
- 若声称提供了结构化数据，**抽样核对内容**（只列**字段名与条目数**，
  **不要抄录考纲正文、题干、例句**）
- **活跃度**：最近一次提交距今多久、有没有 archive、issue 是否无人理

### 2. 按"能不能用"给结论，不要按"来源等级"

对每条问三个问题并**分别回答**：

| 问题 | 说明 |
|---|---|
| **能解决我们哪个阶段的什么问题** | 具体到阶段与用途 |
| **能不能直接用 / 要改多少** | 直接用 / 改数据模型适配 / 只能当参考 |
| **它的许可允不允许我们用** | 落盘 / 再分发，分开答；**权利不明标 unknown，但不因此否掉** |

### 3. 区分三类，**不要混**

- **数据**：考纲条目、真题、词表——**当前最缺**
- **库/轮子**：可直接依赖的代码
- **参考实现**：不能直接用，但能借思路

### 4. 找不到就说找不到

**绝不用模型自己的知识"生成"一份考纲或真题数据冒充检索结果。**
一条诚实的"没找到"，比一份编出来的结构化考纲有价值得多。

### 5. 不要抄录受版权保护的正文

报告里**只列**：repo 名、字段名、条目数、许可、结构描述。
**不要抄录**：考纲正文段落、题干原文、例句、教辅讲解。

## 交付

报告写入 `%TEMP%\kaoyan-probe\report-github-survey.md`：

1. **按阶段分组的候选表**：每行 = repo / 用途 / 事实（star、最近提交、许可）/ 抽样核对结果 / 三类归属 / 可用性结论

6. 严格区分「我实测到了」与「我推断」
