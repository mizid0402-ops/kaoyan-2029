# 附件可靠性独立审查（codex）

## 0. 证据包自检结果（与 index.json 的逐条比对）

结论：**我认为的：证据包可用于“页面声称了什么”的离线初筛，但不能证明摘录与原始响应逐字、逐字节相同。证据包自身关于字节一致性的说明过强。**

### 0.1 我实际核验过的内容

- **我验证过的：** 被审附件当前为 595 行、15885 字节，SHA-256 为 `c99635318bb22179351edc6bb07d1f0883aa8403b73c9d14f3e9896ca6d072a0`，与附件所在哈希目录及 `context.md:10-12` 一致。
- **我验证过的：** `evidence-bundle.md` 总表有 20 条数据行；`index.json` 也有 20 个对象。按顺序逐条比较，20 条的原始 URL、HTTP/失败状态、响应字节数、响应 SHA-256 前 16 位全部一致。
- **我验证过的：** 再从 20 个 `### A1` 至 `### C8` 章节提取元信息独立复核：19 个成功响应的 URL、HTTP、响应字节数、完整 64 位 SHA-256 全部与 `index.json` 一致；C5 在两处都为 SSL 自签证书错误、未取得响应字节（`evidence-bundle.md:834-838`）。
- **我验证过的：** A3 在证据包和 `index.json` 中均为 **102 字节**，不是 `context.md:71` 所写的 103 字节。后者是共享事实基线中的数字错误；应以直接读取的 `index.json` 与证据包 `A3` 字段为准。

第一种比对以总表行为单位，核心逻辑为：

```powershell
$rows = evidence-bundle.md 中匹配 '^\| ([ABC]\d+) \| (https?://...)' 的行
$idx  = Get-Content index.json -Raw | ConvertFrom-Json
逐项比较 URL / HTTP / byte_size / sha256.Substring(0,16)
```

第二种比对不使用总表，而从每个 `### A1...C8` 章节下的 `URL` 和元信息行提取完整 SHA-256，再与 JSON 对象比较。两种方法分别得到 20 个总表行和 20 个证据章节，集合与顺序一致。

### 0.2 证据包不能证明的部分

- **我验证过的：** `evidence-bundle.md:3-5` 声称磁盘证据文件的 SHA-256/字节数与 `index.json` 不一致就中止；但同文件 `:14-31,33` 明列 18 个文本响应的“本地文件 sha256”与“响应 sha256”不同，理由是文本已重编码。计数用两种方法复核：一是总表中“否（文本已重编码）”共 18 行；二是 19 个成功响应减去唯一哈希相同的二进制 C7，仍为 18。
- **我认为的：** “重编码后的文本能代表页面语义”可以成立，但这不等于“本地文件与响应字节一致”。在禁止读取原始抓取文件、禁止运行构建器的边界下，我无法独立核验摘录确实由相应原始响应生成，也无法排除解码、截断或摘录选择错误。因此我只接受“响应元数据与 index 自洽”，不接受“摘录已被我做过字节级认证”。

### 0.3 泄漏闸门检查

- **我验证过的：** 我逐段检查了全部 fenced 摘录，并用两类只读正则扫描长 Latin/CJK 片段。没有发现可辨认的英语真题原文、题干、选项或答案原文；C7 也只有元信息，没有 PDF 内容（`evidence-bundle.md:888-892`）。
- **我验证过的：** `evidence-bundle.md:875` 仍保留了一整行较长的第三方中文说明，包含 2026 英语一题型数字和阅读主题摘要。它看起来是站点 FAQ/二次概述，不是试题或答案的逐字原文，因此我不把它判为已经发生“真题原文泄漏”。
- **我认为的：** 上述长行说明泄漏闸门并非“所有长中文都删除”；它只足以支持“没有发现明显原文”，不能证明零泄漏。该行对本审查也不是必要证据，后续证据包宜只保留标题、字段和最短命中上下文。

## 1. 裁定：source_tier = community_archive / may_define_syllabus = false

### 1.1 档位

**我认为的最终裁定：`source_tier = community_archive`。**

依据是实际代码，而不是附件自己的 A+/A/B 等级：

- `material.py:88-95` 定义 `trusted_reprint` 为“大型机构或可信站点的转载，须交叉验证”，`community_archive` 为“论坛、网盘、个人整理：只能用于查漏与线索”。
- 被审对象是未署名、无发布组织、无原始出处说明的用户提供第三方整理稿。它链接到若干较强来源，不会因此继承每个链接的来源等级。
- `material.py:571-575` 还明确规定，未声明可信度时默认最弱档 `community_archive`。

**我验证过的当前冲突：** `data/materials.yaml:765-808` 已把同一 SHA-256 的附件登记为 `trusted_reprint`，同时又写明“未署名（用户提供的第三方整理稿；整理者与原始出处均未标注）”。这两个字段互相不相称；我不采信该预先登记的裁定。

### 1.2 `may_define_syllabus()`

**我验证过的：`may_define_syllabus() = false`。**

`material.py:101` 只允许 `official / official_publisher / university` 三档；`material.py:441-447` 的实现只是：

```python
return self.source_tier in SYLLABUS_AUTHORITATIVE_TIERS
```

`community_archive` 不在集合中，所以结果为 `false`。

### 1.3 后果

- **我认为的：** 附件只能作为查漏、URL 发现和待核验主张清单；不能定义数学一/英语一考纲节点，不能给知识树增加范围，不能作为题型题量/分值的最终来源，也不能把第三方答案提升为官方答案。
- **我认为的：** 可将 A1、A2、A4、B3 等底层页面分别登记并分别定级；“底层页面可用”不等于“附件整体可用作证据”。
- **我认为的：** 即使 B3 单独定为 `university`，也只说明来源主体系高校。`may_define_syllabus()` 当前代码只检查 tier、不检查 `material_kind`；拿一份真题解析去定义考纲，属于对该方法的语义误用。

### B3 额外结论

- **我验证过的：** URL 主机名确为 `www.tjrac.edu.cn`，页面自称天津仁爱学院数学教学部，且列出 PDF 附件。
- **我认为的：** 最窄且诚实的称呼是“高校数学教学部发布的真题及答案解析资料”。证据没有显示这是教育部教育考试院的官方参考答案，也没有显示教学部取得官方授权；应按教学/备考解析而非官方答案使用。
- **我认为的：** 它不能因域名为高校就定义考纲。即使其独立条目 tier 设为 `university` 后，当前 `may_define_syllabus()` 会机械返回 true，该 PDF 的主题仍是“真题及答案解析”，不是“考纲内容”。用它决定知识树范围是材料类型与用途错配。

### C7 额外结论

- **我认为的：** 元信息不足以最终判断文件格式；只有检查魔数/交叉引用结构或由 PDF 解析器成功打开，才能把“真 PDF”从高概率推断提升为已验证事实。本轮边界禁止读取该原始文件，所以结论必须保留为 `PARTIAL`。
- **我验证过的规则后果：** 无论它是否为真 PDF，均**不能进入 `data/raw_materials/`**。`docs/资料可得性侦察.md:214-218` 禁止登记题干、答案原文和批量抓取；数学专项规则 `:319-321` 同样禁止题干、答案及 PDF/扫描件；项目级结论 `:451-454` 禁止建立正文库、答案库和批量抓取/OCR。允许的落点只有远程 URL、年份、类型、响应哈希、权利状态等元信息。

### 是否把回忆版/机构解析当作官方答案

- **我验证过的：** 附件 `:6,192,408,432` 明确说 2026 机构答案只是参考，不是官方标准答案；这一点没有直接冒充。
