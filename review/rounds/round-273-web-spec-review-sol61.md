## 必须改

### M1 / MAJOR：统一今日视图不能承载现有 CLI 的全部输入与依赖边界

位置：`today.md:23-32,52,83-84`；`ky/__main__.py:244-287,387-412`。
唯一静态反例：没有注册表的临时目录中，显式传合法 `--config`、`--items` 的 `preflight --json`。
现行路径允许 `workspace=None` 并输出；新 `load_today(Workspace, day)` 强制三项登记，无法保留此调用。
同一根因也使 `--usage`、显式队列/配置、裁剪策略无法传入；预检还会被额外的出题依赖阻断。
必须明确：共享的是接受已加载上下文与策略的计算端口，CLI 保留覆盖参数、可选注册表及各自依赖。
对照验收需点名上述旧分支，包含退出码、stdout/stderr 字节；不能只比较网页默认工作区路径。

### M2 / MAJOR：失败零写入承诺与完成事件先落盘冲突，且缺少恢复路径

位置：`web.md:45-46`、`today.md:65,70-71`；`ky/__main__.py:1674-1679,1755-1767`。
唯一代码证据：`tests/test_cli.py:1212-1219` 明确守护“推进失败仍保留已写完成事件”（只读，未运行）。
日常磁盘失败/中断可发生在完成事件写成之后、队列提交之前；刷新已有 `recorded`，重交又被 §4.3 拒绝。
因此不能把所有失败描述为没有写入，也不能让页面将“事件存在”等同于“队列推进成功”。
必须区分写前拒绝与部分完成，给出仅推进已存事件的恢复路径（可由 AI 执行），保留 completion ID 防重放。
此项须与 CLI 基线并存，不可为了网页承诺回滚或改写原有完成事件；§6 增补这一种失败状态的验收。

### M3 / MAJOR：缺题页面把未声明的自评自动记为默写核对

位置：`today.md:68-69`、`web.md:35,54-57`；D3 见 `docs/阶段2.5-接缝收口.md:115-123`。
唯一静态反例：缺题项只显示“请让 AI 补题”，用户未对照笔记而选择 correct；记录自动写 `recall_vs_notes`。
`ky/schedule/completion.py:107-117` 会将它当已核对结果参与推进，页面没有要求用户声明已完成对照。
必须在缺题项明确写“先默写，再对照笔记；以下选择是对照后的结果”，否则仅允许跳过。
不要求系统验证笔记材料，也不要求必填 `question_ref`；M10 明确允许信任用户的核对声明。

### M4 / MAJOR：M33 课表映射缺少 M16 必须展示的大节数

位置：`today.md:40`、`web.md:32,41`；`ky/timetable/calendar.py:163-173,187-203`。
唯一代码证据：`blocks = _block_count(periods, school)`，随后分别输出 `periods` 与 `blocks`。
节次列表不是大节数，分组依赖学校的大节规则；M16 不能仅由当前映射推导，另读学校数据又违反分工。
必须让 M33 输出 `blocks`，明确其来自 `DaySchedule.blocks`；同时明确 term/weekday 的映射与无课表日的 null。
