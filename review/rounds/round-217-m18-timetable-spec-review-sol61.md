结论：**FAIL**。有两条必须改：候选学校档案校验流程没有可执行入口；第 11 节暂定数据与其声明的推算依据矛盾。核心分钟公式、优先级和不设课表硬上限的方向通过。

评审范围：静态阅读任务书指定规格、两份 YAML 和相关现有代码；补读 M13/M26 来源端口及 M9 裁剪代码以核对接缝。没有运行测试、没有联网、没有读取 PDF 或仓库外文件。只写本报告，没有实现修改，也没有提交。

证据边界：§9 是本轮提供的用户选择记录，以下按它评审；未独立核对原始对话。所有分钟案例均为按草案手算，不是实现执行结果。内部转录自洽不代表与原始 PDF 一致。

## 一、必须改

### R1：先 check 再登记的流程缺少候选文件入口（§5、§7、§8）

**具体输入**：已有工作区登记用户学校 `<school>`；新增学校 `new_school` 的合规档案放在
`staging/new_school.yaml`，尚未登记。档案有两个节次 08:00–08:45、08:55–09:40，
`blocks: [[1, 2]]`。拟增加学期 `new-term`，第 1 周周一 2027-02-01，18 周，引用
`new_school`，周一第 1–2 节、周次 `1-18`。规则为学习窗 08:00–22:00、缓冲 15、
最短空档 25、每大节扣 15、cap 120；若正式生效，当天应算 105 分钟。

**草案给出的结果**：§5 要求候选档案经 `ky timetable check` 和用户确认后再登记；
§8 的 check 却只能校验个人课表与「全部已登记学校档案」，没有候选路径参数。
维持未登记状态，check 根本没有检查这份新档案；提前让生效课表引用它，则 §7
报 `semesters[i].school` 未登记违约。通过 `--workspace` 临时建一份候选注册表可能绕开，
但草案没有规定这个流程，也没有说明如何映射候选学校与候选课表。

**应有的结果**：不修改生效注册表即可明确检查候选学校文件，返回针对该文件的合规结果；
之后才确认、登记、生效。最小修法是在 §8 增加候选学校检查入口，如
`ky timetable check --school FILE`，其语义只加载该档案并校验内容，不要求已登记键；
登记键相等检查仍在正式工作区加载时执行。也可以明确规定临时候选工作区流程，
但要完整写出步骤，不能让「check 成功」被误读为未登记候选文件已检查。

这是日常新增另一学校的流程断口，不是恶意输入问题，也不是要求本轮实现导入器。

### R2：第 11 节数据与「按同一规律推算」的依据矛盾（学校数据及 §9）

**已确认的内部事实**：用户学校档案注释声明大节间隔 30 分钟，第 11 节按同一规律推算。
第 10 节结束 20:10；`blocks` 把第 11 节独立为一个大节，但第 11 节写 20:20–21:05，
实际跨大节间隔只有 10 分钟。按声明规律应暂定为 **20:40–21:25**。

**具体输入**：使用上述档案；学期第 1 周周一 2026-09-07、18 周；该日一门课第 10–11 节，
周次 `1`，无例外。学习窗 08:00–22:00、buffer 15、min_gap 25、扣减 0、cap 840。

**草案给出的结果**：当前数据的缓冲占用并集为 19:10–21:20，空闲为
08:00–19:10（670 分钟）和 21:20–22:00（40 分钟），得到 **710 分钟**。

**按声明规律应有的结果**：若第 11 节仍独立成大节，暂定时刻为 20:40–21:25；
缓冲区间在 20:25 相接，并集为 19:10–21:40，空闲 670 + 20 = **690 分钟**。
当前真实个人课表未使用第 11 节，所以这不是宣称当前课表日预算已经差 20 分钟；
但普通用户后续增加晚课就会使用这一暂定数据。

**所需修订**：统一第 11 节时刻、blocks 和注释依据。如果另有理由让 10–11 属于同一大节，
应明确修订 blocks 与依据；如果仍坚持 20:20，应写明它是另一项待确认假设，不能说按
「大节间 30 分钟」推得。保留 `unconfirmed: true`。本评审无法确认学校真实第 11 节，
20:40 只是按本轮给定规律推导，不能升级为官方作息事实。

## 四、接缝结论

### M26 / M8 / M9：可保持未登记课表路径不变

现有 M26 只返回 availability/config；preflight 与 M19 只在 availability 来源传 override
和 drop_when_short。扩展到两个来源，只要 timetable=None 时不加载学校、不增加字段或输出行，
旧条件仍完全相同。只登记学校而不登记个人课表也应走旧路径。
不能根据「课表对象存在」切换短预算策略：在学期外实际来源为 config，仍保持 strict。
固定基线 e381792 的字节对照要求合理，本轮没有运行对照，不能声称已经验证兼容性。

示例：配置 120，hard_max_ratio=0.6，课表 75，则日硬复习上限 floor(75×0.6)=45。
路线两个等配额科目各 30 时，M8 缩放为 23/22（余数相同按 ID 排序），不能把未缩的 60 传给 M9。
配置硬复习上限仍为 72：一项 50 分钟复习当日延期，不应因课表较短而判必须拆分；
现 M9 使用 max(配置硬上限, 当日硬上限) 判 unschedulable，接法成立。
冻结时仍先覆盖为 0 且不传阶段配额；课表不能解除冻结或把配额重新带回来。

### M19：null 改为对象合理，版本不是硬性必须升

只登记课表时，当日对象 `{"minutes":75,"source":"timetable"}` 能让规划者读到真正基数，
比继续 null、仅暴露 default_daily_minutes=120 合理。学期外应为配置来源对象，
与现有「已登记手填但该日无条目」的 config 对象规则同构。

这是 source 枚举的扩展，严格旧消费者不能自动视为兼容；但没有本轮证据证明存在这样的消费者。
本项目已有 schema_version=1 下新增 route_plan 等字段的先例，因此不凭版本号本身判必须改。
建议同步修订 availability.md、planner_port.md、route_plan.md 的来源说明，
明确新 enum 和 null 的判定，旧包仍合法；若已有独立消费者封闭枚举，再设计版本迁移。
无条件把全部包升到 2 会违反未登记课表的逐字节不变要求。

`availability` 是对当日解析结果的既有字段名，容易被误认为硬上限；建议文字明确
source=timetable/config 是参考、只有手填单日条目构成 M13 硬上限。
本轮不要求重复建一个等价 daily_budget 对象。

### M27：一次加载足够，但要贯通整个搜索

同一不可变 TimetableCalendar 包含全部学期、规则和所引用学校，就足以覆盖 resume 的
366 天搜索；不能只传 D 当日分钟或只加载 D 所在学期。应把同一对象从 plan_resume 贯通
到每个候选日的 resolve_day_budget，学期外自然回配置。多个学期共用学校时，学校也只读一次。
来源摘要必须来自用于解析的同一份原始字节，不能再次读文件计算 hash。
跨天调用纯 day/minutes_for 不等于重复读源文件。没有理由加网络、每天重载或延长搜索窗。

冻结阈值使用配置容量，与 freeze.md 的 D11 细则一致。配置 120、hard ratio=0.6、
backlog_days=3，阈值是 216；课表 75 不会降至 135。
冻结判定与恢复时排入哪天是不同职责，不应把阈值改为浮动课表容量。

### M13：不增加课表硬上限

课表 75、空档 450、AI 声明 available_minutes=200：在其他不变量、冻结门均通过时应允许，
因为 75 是默认参考，不是物理可用时间。若手填同日 90，声明 200 则仍拒绝。
把课表 75 当硬上限会直接违反 §9；额外把 free_minutes 作硬上限也没有用户选择支持。
极端不现实的 AI 计划可以提示和人工审阅，不应借评审私自加入另一项硬约束。

## 五、建议改

1. **补齐格式表**：个人文件的 schema_version 明确为精确整数 1；semesters、courses、
   exceptions 的容器类型、必填/缺省和能否为空；name 非空；weekday、weeks、periods 键等
   整数均排除 bool。日期统一为 YAML date 或严格 ISO 字符串并拒绝 datetime。
   例外字段写为互斥形状，避免同时带 date 与 from/to。现草案有意图但不够完整，
   宜在实现任务书前写清，不需要引入新业务规则。
2. **引号规则按值还是按语法**：坚持 HH:MM 字符串并拒绝 YAML 1.1 读出的数值合理。
   但未引号的 `08:00` 可被加载器保留为字符串，单靠「非字符串拒绝」不能保证所有时刻
   都带引号。更简单的等价规则是要求解析后的值为严格 HH:MM 字符串，并建议作者始终加引号；
   若确要强制引号语法则需 scalar style 校验，没必要为本目的复杂化。
3. **blocks 的相邻含义**：明确相邻指节次编号，不要求时刻无间隙。
   非空 blocks、非空子块及精确整数应写清。不要自动按时间间隔猜大节；另一学校提供其划分即可。
4. **不确定时刻对普通入口可见**：unconfirmed 布尔及 show/check 标记合理。
   建议 preflight 的课表解释行在当天使用不确定节次时也标记；否则用户只看日预算可能看不到假设。
   不必因此禁止正常规划。
5. **来源够当前使用，别误标**：official/user_statement 能覆盖官方原始资料和用户口述，
   当前足够。若将来新增由 AI 自行估计的整份学校档案，需要 inferred 类别或明确记录推断依据，
   不能以 official 名义登记。per-period 的 unconfirmed 应保留，不用现在设计全面来源系统。
6. **来源路径、解释字段和 CLI 消歧**：sources 的路径是绝对还是相对工作区须固定；
   DaySchedule 的 blocks 是计数还是块列表、cap 是扣减前还是后须定义。
   follow 的 week 建议指实际日所在周，目标周从 followed 推导；weekday_used 指目标星期。
   多学期 show --week 缺省如何选择、--week/--date 互斥及越界退出也需定清，不能暗读当前时间
   决定纯端口结果。
7. **M0 同步范围**：§5 写同步 workspace.md 是正确安排，也应补 Workspace 公共字段及
   require/write_target 对两个新键的规定。未知字段拒绝照旧；被引用学校缺失/无效 fail-closed，
   不得当作没有课表回退。生产只读所引用学校、显式 check 校验全部已登记学校的区别合理。

## 六、不改及可维护性

M26 定义窄协议、M18 实现、M8 解析预算、CLI/M19/M27 负责装配，依赖方向清楚，符合 D7。
不要把课表预先压成 Availability.days：那会丢失 timetable 来源、None 的边界与手填硬上限的区别。
也不必把 M18 的学校和课程结构暴露给 M8/M9；它们只需要 minutes_for。
CLI 解释行需要 day() 时由装配层访问 M18，不让 M26 import M18。

同校下一学期只增加 semesters 项，另一学校新增档案再引用，都可以不改计算代码。
允许跨午休节次范围、单节大节、不同长度大节是优点。冬夏作息版本化明确另阶段处理，
不能据此宣称 v1 支持所有学校的一切历史作息，也不要求本轮扩 schema。
不增加任务时段拆分、ICS/CSV 导入、投影或额外安全护栏。

人工按 weekday / weeks / periods 交叉检查当前课程：没有发现同一天同一节的课程重叠，
