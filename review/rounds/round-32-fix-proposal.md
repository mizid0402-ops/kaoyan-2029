## 0. 缺陷与根因（已复现）

`tools/verify_tree.py` 存在的唯一意义是"把树弄坏必须变红"。而它选择检查分支的依据是
**`scope == "chapter"` 这个可被数据改写的字段**：

```
删掉全部 24 个章节点        → 无任何节点带 scope=chapter → 判为 structure → 0 条失败，ALL CHECKS PASSED
只把 24 个章的 scope 改标   → 同上
只删 1 个章                 → 正确变红（2 条失败）
```

**根因：推断的输入选错了。** `scope` 是数据里可自由改写的标签，不是结构事实；
用它决定"该跑哪套检查"，等于让被检查对象自己选择考卷。

## 1. 两方建议的核心差异（主控实测裁定）

| | Codex | Claude |

**主控实测裁定（见 §2 数据）：两方案不冲突，可组合，且必须组合。**

## 2. 支撑裁定的实测数据

```
命名空间（ID 首段）分布：
  cs408 基线/主表  {'cs408': 403} / {'cs408': 410}   单一命名空间
  math1            {'math1': 69}                      单一
  eng1             {'eng1': 24}                       单一
  → 三棵树命名空间互不相同

语法标记分布：
  cs408  章正则 24、节正则 116、裸 .chapter 0、content+req 对 0
  math1  章正则 0、 节正则 0、  裸 .chapter 22、content+req 对 22
  eng1   全部为 0   ← 合法树，却没有任何标记
```

### 决定性事实

**eng1 是合法树，却没有任何 cs408/math1 标记。** 所以在"只看语法"的路由下，
"没有标记"必须解释成 `structure`。**但一棵被删光章的 cs408 树，同样没有任何标记。**

> **两种情况在语法路由下发生碰撞，而被信任的恰恰是被破坏的那一个。**

**命名空间路由不碰撞**：cs408 树无论删掉什么，命名空间仍是 `cs408`，永远不可能被当成 eng1。

**结论：命名空间是承重信号，语法是校验信号。**

## 3. 建议表（主控合成）

### F1 —— 路由改为按命名空间选定 profile（承重）

```
SUPPORTED_ROOT_SHAPES = {"cs408": "cs408", "math1": "math1", "eng1": "eng1"}
roots = {id.split(".")[0] for id in all_ids}
要求 len(roots) == 1，否则失败
要求 root ∈ SUPPORTED_ROOT_SHAPES，否则失败
```

- **不得保留"无标记 → structure"的负向兜底**
- **`eng1` 必须成为显式 profile**，不再是"其他情况的默认"

### F2 —— profile 内 ID 语法校验（防误标）

- cs408 profile：章必须匹配 `<subject>.<domain>.chapter-NN`，节必须匹配 `<...>.chapter-NN.section-NN`
- math1 profile：章必须匹配 `<...>.chapter`，且每章必须有 `.content` 与 `.requirements` 两个同级节点

### F3 —— 双向双条件（防改标签，命中 P3）

| 条件 | 失败消息 |
|---|---|
| id 符合该 profile 的章语法，但 `scope != "chapter"` | `id matches chapter pattern but scope={scope!r}` |
| `scope == "chapter"`，但 id 不符合该 profile 的章语法 | 反向同款 |

**F1 挡住 P1（删光章），F3 挡住 P3（改标签）。缺任何一条都会留一个绕过口。**

### F4 —— 识别不明确一律失败

- 命名空间混合或未知 → 失败
- 同时匹配多种语法标记（歧义）→ 失败
- **绝不回退到最宽松的分支**

### F5 —— 保留 round-31 已修好的部分

四棵真实树必须仍然全过；**不得回退 round-31 对 cs408 树形与命名不匹配的修复**。

## 5. 主控自行审查（这部分是审查记录，不是建议）

### 5.1 我为什么把承重信号判给 Codex

**因为它可被实测证伪，而 Claude 的路由不可。** 我做了决定性对照（§2）：
eng1 与"被删光章的 cs408"在语法上**完全同形**，无法区分；命名空间上则天然分离。
**Claude 自己的 P1 复现结果（cs408 → structure）就是这个碰撞的实例**——
它需要额外加 F3 才能活下来，而 F3 并不解决路由问题，只是把失败挪到下一道检查。

### 5.2 我为什么保留 Claude 的 F3

**因为 Codex 的方案单独用会漏掉 P3。** 改标签不改变命名空间，
所以命名空间路由会照常选中 cs408 profile**并一路通过**——
`scope=section` 的节点在 cs408 profile 下本来就被当作节，不报错。
**F3 的双条件正是唯一能命中这条的检查。**

### 5.3 我认可 Claude 的一点

它指出了**对称漏洞**：若 math1 只用裸 `.chapter` 做标记，
则"删光 math1 的章节点"同样会滑落到 `structure`。
**在命名空间路由下这条自动消解**（math1 永远在 `math1` 命名空间），
但它提出这一点说明它检查了对称性，值得记。

### 5.4 我不采纳的部分

- **不采纳"无标记即 structure"**（Claude）：这正是缺陷本身
- **不采纳"仅用语法标记路由"**：eng1 与"被破坏的 cs408"会碰撞（§2 实测）
- **不采纳把 F1 与 F3 二选一**：二者各挡一条攻击路径，缺一不可

### 5.5 本建议表的代价（必须写明）

| 代价 | 说明 |
|---|---|
| **新增一棵树必须显式登记命名空间** | 否则加载即失败。这是**有意的**：宁可拒绝新树，也不要静默降级。但将来接入第四棵树时，必须改 `SUPPORTED_ROOT_SHAPES` |
| **ID 语法成为契约的一部分** | cs408/math1 的 id 拼写习惯被写进验证器。这是**既有耦合**（round-31 已在用这些正则），非本表新增 |
| **`scope` 从"分支依据"降为"一致性证据"** | 这是语义变化，需在验证器文档里写明，否则后人会再把它当分支依据用 |
