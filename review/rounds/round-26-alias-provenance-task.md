# 任务：定位 27 条 alias「尾巴」的真实来源，据此决定修法

## 背景

`data/structured_materials/cs408/knowledge_tree_weighted.yaml` 里有 **410 个节点**，每个节点带 `aliases`。

主控核验时发现：**209 条 alias 里有 27 条无法在源 B（2022 PDF）里整串命中**。逐条看下来，
这 27 条**都有很长的前缀确实存在于源 B**，但**完整的 alias 不在**；多出的那一截（下称"尾巴"）
**在源 A（2026 HTML）里也找不到**。

**已确认的事实（不要重做）**：

| 检查 | 结果 |
|---|---|
| alias 整串在源 B 命中不了的 | **27 / 209** |
| 这 27 条的前缀在源 B 命中 | **27 / 27** |
| 尾巴在源 B 命中 | **0 / 27** |
| 尾巴在源 A（2026）命中 | **0 / 27** |
| 整条 alias 在源 A 命中 | **0 / 27** |

**抽样看到的两种形态**（**这提示了两种可能的原因**）：

1. `加减运算:补码加减运算器` + 尾巴 `,标志位的生成`
   —— 尾巴像是**说明的后半段**，前半段在源里
2. `文件系统的全局结构(Layout)文件系统在外存中的结构` + 尾巴 `,文件系统在内存中的结构。`
   —— 同样是**说明被拆成两半**

**所以有两种可能的原因，修法完全不同**：

| 可能原因 | 判断依据 | 对应的修法 |
|---|---|---|
| **甲：跨页/换行拼接错位** | 尾巴在 PDF 的**下一页或下一行**能找到，只是中间被分页/换行切断，而构建脚本拼接时多接了或接漏了 | **修构建脚本的跨页拼接逻辑**，alias 恢复成能整串验证，**不需要新字段** |
| **乙：来自我们未持有的版本** | 尾巴在 PDF 里彻底找不到，可能来自 2022 官方完整版或另一份转录 | **改 schema**：alias 只存能验证的部分，尾巴另存 `extra_text` + 标 `unverified_version_mismatch` |

**你的任务就是分清这 27 条各属于哪一种。**

## 你要做的

### 1. 逐条定位（27 条全部）

对每一条无法整串命中的 alias：

- 找到它的**前缀在源 B 里的位置**：**页码 + 页内字符偏移**（或行号）
- 输出**该位置前后各约 200 字符的原文上下文**（用于判断尾巴是否紧邻其后）
- **在源 B 全文里查找"尾巴"的首 6–10 个字符**：
  - 若找到 → 记录位置、以及**它与前缀位置之间隔了多少字符**、**是否跨页**
  - 若找不到 → 记录"未找到"
- 同时**在源 B 里查找"尾巴去掉首字符后"的变体**（因为标点/全角半角可能不同）

**判定规则（写进报告，并逐条给结论）**：

| 情况 | 判定 |
|---|---|
| 尾巴（或其变体）紧邻前缀之后，中间只隔**换行/分页/空白** | **甲：拼接/跨页问题** |
| 尾巴出现在源 B 的**其他位置**（不紧邻） | 甲，但属**重排**，要记录具体位置 |
| 尾巴在源 B **彻底找不到** | **乙：来自别的版本** |
| 尾巴只有**一部分**能在源 B 找到 | 混合，**分别记录前后两截** |

### 2. 给一张完整判定表

| # | 节点 id | 前缀长度 | 尾巴 | 尾巴位置（页/偏移） | 是否跨页 | 判定 | 依据 |
|---|---|---|---:|---|---|---:|---|---|

**27 行，一行不能少。**

### 3. 汇总结论

- **甲、乙各多少条**
- **如果绝大多数是甲** → 说明是构建脚本的拼接缺陷，**并指出缺陷在脚本的哪一步**
  （去看 `tools/round24_build_weighted_tree.py` 或它调用的抽取脚本，
  定位跨页/换行拼接的代码，**说明它为什么会多接一段**）
- **如果多数是乙** → 说明 alias 混装了来源，**给出 schema 修改建议**

### 4. 抽样复核（证明你的定位不是碰巧）

挑 3 条判为"甲"的，**展示完整的前缀上下文 + 尾巴上下文 + 两者之间的原始字符**，
让主控能一眼看出确实是跨页/换行造成的。
