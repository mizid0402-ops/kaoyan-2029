# 任务：GitHub 现有项目可用性评估表（中英双语检索）

## 本轮目的（与之前两轮检索不同）

前两轮找的是**数据**（考纲、词表）。**本轮找的是"能接进当前项目的轮子"**，
产出一张**可用性评估表**，供**三方交叉核验**，并据此决定**下载引入哪些**。

**判断标准不是"这个项目好不好"，而是"它能不能省掉我们本来要自己写的东西"。**

## 当前项目实际需要什么（据实列出，不要泛泛搜）

| 阶段 | 我们需要的能力 | 现在我们自己写到哪了 |
|---|---|---|
| ① 知识树 | 树结构 + 多源加权 + **可验证的溯源** | **已有自研**：`ky/knowledge/knowledge_point.py` 严格契约、`tools/verify_tree.py` 变异测试 oracle、408 双源加权树 |
| ② 复习调度 | 间隔重复 / 遗忘曲线 / 积压处理 / 容量规划 | **已有自研确定性排序核**（全序键：逾期天数、延期次数、遗忘次数、科目落后率、due_date、类型优先级、自评、review_id），经 4 轮审查 + 变异测试 |
| ③ 本机只读 Web | SQLite → 只读投影；预算 120 分钟/天 | **未开始** |
| ④ 课表协同 | `.ics` 解析、带约束排程、临时覆盖（调课/考试周/假期/实习） | **未开始** |
| ⑤ 可视化 | 学习进度 / 能力画像 / 目标差距 / 课表周视图；政治用柱状图 | **未开始** |
| ⑥ 数据管线 | YAML 严格契约校验、哈希锚定、确定性重跑 | **已有自研**（且已证明必要） |

**已知项目约束（评估时必须守住）：**

- **本机单用户、文件为准**；Web 是**只读投影**，SQLite **可重建**
- **Python 3.12** 为主；无 Node 构建链
- 预算固定 **120 分钟/天**，四科占比 数学一 40% / 英语一 20% / 408 40% / 政治未激活
- **AI 生成内容永进不了频率统计与验收**
- 项目已有**三处同名但不同义**的 `weight` 字段（学科时间预算 / 题目→知识点置信度 / 来源支持度）
  —— **引入任何带 `weight` 概念的库都要评估命名冲突**
- 复习排序核**已经过 4 轮审查**，**引入 SRS 是"叠加"还是"替换"必须评估，不要默认替换**

## 要评估的对象（按优先级）

### 高优先：③④⑤ 三个未开始阶段
- ③ 本机只读 Web：SQLite 只读投影、单文件/无服务优先、Python 侧
- ④ 课表：`.ics` / `icalendar` 解析、带约束排程、**临时覆盖与恢复**的处理模式
- ⑤ 可视化：雷达图（能力画像）、甘特/周视图（课表）、柱状图（政治）
  —— Python 侧优先（plotly 类）；若只有前端库，**必须说明它需要 Node 构建链，与项目约束冲突**

### 中优先：②的"叠加"候选
- FSRS 各语言实现及其实用性；**重点评估能否作为排序核的一个特征维度叠加**，
  而不是替换掉现有核

### 低优先：①⑥ 的对照实现
- 已有自研且经审查，**除非能显著减少维护面**，否则不引入

## 硬性要求

### 1. 每条给可核验事实，禁止只转述 README
- repo 全名、URL、**star 数、最近提交时间、许可证**
- **实际下载**了哪些文件、字节数、**SHA-256（现算）**
- 是否 archive、issue 是否无人理（给具体数字与日期）
- 若声称提供某能力，**抽样核对**：只列**字段名/函数名/条目数**，不要抄正文

### 2. 按三条互不推导的轴分别回答
| 轴 | 问什么 |
|---|---|
| **① 能解决哪个阶段的什么问题** | 具体到能力，不要"很有用" |
| **② 能直接用还是要改多少** | 直接用 / 改数据模型适配 / 只能当参考；**给出改动量级估计** |
| **③ 许可证允不允许** | 落盘 / 再分发**分开答**；权利不明标 `unknown`，**但不因此否掉** |

### 3. 必须评估"与自研的冲突"
- 与现有排序核/契约/`weight` 命名**是否冲突**
- 若冲突，**给出"叠加"与"替换"两种做法的代价对比**
- **不得因为"外面有现成的"就建议替换掉已审查的自研核**

### 4. 中英双语检索（这是本轮的明确要求）
- **中文关键词**（注意：多个中文词做 AND 组合时 GitHub API 极易返回 0，
  应**用单关键词多搜几轮**）：考研、考纲、大纲、真题、错题、复习、课表、倒计时、背单词
- **英文/拼音关键词**：`kaoyan`、`China postgraduate entrance exam`、`spaced repetition`、
  `FSRS`、`interval scheduling`、`timetable solver`、`course scheduling`、
  `radar chart learning`、`study dashboard`、`obsidian vault`、`anki deck`
- **topic 检索**：`topic:spaced-repetition`、`topic:kaoyan`、`topic:study-planner`、
  `topic:education`、`topic:visualization`
- **两个语种的结果要分别报告**，并说明**哪个语种找到了哪些**——
  若某语种一无所获，那也是有用结论

### 5. 找不到就说找不到
**绝不用模型自己的知识"生成"一个不存在的 repo 或凭印象描述其能力。**
每条事实必须有 URL 与实测支撑；**无法实测的必须标为「推断」**。

### 6. 不要抄录受版权保护的正文
报告里只出现：repo 名、URL、字段名、函数名、条目数、许可证、结构描述。
**不要抄**：考纲正文、题干、例句、教辅讲解、词表释义文本。

## 交付：一张表 + 一份说明

**表列**（每行一个候选）：

| repo | 阶段/能力 | star | 最近提交 | 许可证 | 实测下载与哈希 | 三轴结论 | 与自研冲突 | 建议（引入/参考/不用） | 改动量级 |
|---|---|---|---|---|---|---|---|---|---|

**另附：**
1. **中英文检索结果对照**（各找到哪些、分别多少）
2. **"最该引入的三样"** 及理由——**如果确实有的话**；没有就直说
3. **"明确不建议引入"清单**及理由
4. 「我试过但没找到的路径」——具体搜索词与返回数
5. 「我实测到了」vs「我推断」
6. 没有把握的地方至少 3 条

## 纪律

- 工作目录：`%TEMP%\kaoyan-probe\ghsurvey3\`
- **不要修改** `F:\workspace\kaoyan-ai-system` 下任何文件（只写你自己的报告到临时目录）
- 不要执行 git
- 本机**没有 `rg`**，用 Glob/Grep 或 `Get-ChildItem -Recurse`
