# 第 225 轮：M29 课表导入 / 导出规格细则评审

结论：**FAIL**。导入暂存、人工确认、两种适配器及本地日历导出的总体方向符合 §8；但隐私路径、暂存编辑与哈希、重复事件处理、PDF 记录边界、发布流程及 M18 校验接缝仍需补规则。当前不宜直接发实现任务书。

证据范围：静态阅读任务书所列规格和代码，补读依赖声明、Git 忽略规则及现有只写一次发布代码。以下输入全部是合成数据；数字为按草案推导，不是执行结果。没有运行测试或解析探针，没有读取真实 PDF、个人文件或仓库外文件，没有联网。决策者的 PDF 探针结论按任务书提供的事实使用，无法独立验证其适用范围。本轮只写本报告。

## 一、必须改

### R1：只提醒导出路径不受忽略，违反用户的个人数据选择

涉及 §1、§6、§8。

**具体输入**：有效合成课表，运行 `ky timetable export-ics --from 2025-09-01 --to 2025-09-08 --config C --out exports/demo.ics`；`exports/` 没有 Git 忽略规则。

**草案结果**：写出含课程内容的文件，只打印提醒。§8 却明确要求导出文件在 gitignore 路径下，没有授权提醒后继续写的例外。

**应有结果**：仓库内目标不满足隔离要求时，在任何写入前拒绝，提示改用忽略路径。若要允许此种导出，需要用户改变选择，不能由实现者默许。

同一问题还包括暂存及备份：Workspace 允许登记其他 staging 路径；“已登记”不等于“被忽略”。例如只忽略 `local/table.yaml`，其同目录的 `table.previous-<hash>.yaml` 不一定受忽略。必须在写前核对每类最终文件及临时文件的隔离路径，或者明确约束为受整体忽略的目录。已经被 Git 跟踪的文件也不能因新增 ignore 规则被视为安全存放点。

本条是普通命令违反明确选择，不是恶意泄漏场景。对仓库外的用户导出目标如何判定“不会进本仓库”，也应单独写明；无需为了这一点扫描其他仓库。

### R2：允许手工添加例外，却没有更新内容哈希的可执行规则

涉及 §2、§5.1。

**具体输入**：导入得到 `term-a--H.yaml`，学期从 `2025-09-01` 开始、两周。用户按 §2 指引，把 `exceptions: []` 改为：

```yaml
exceptions:
  - {date: 2025-09-02, kind: no_class}
```

然后运行 `ky timetable apply --from-staging staging/timetables/term-a--H.yaml --dry-run`。

**草案结果**：semester 属于哈希内容，修改后摘要是 H2，文件名仍是 H；§5.1 因哈希不符拒绝。用户被要求完成的正常编辑无法直接应用。

**应有结果**：明确一种完整流程。可以规定人工编辑后通过重新校验/重新封装命令生成 H2 文件，再 apply；也可以将可编辑提案与不可变导入快照分开。不能只写“手工加进去”，再让实现者决定是否放宽哈希或偷偷重写文件名。

同时补齐规范 JSON 的对象转换：示例 YAML 的无引号日期会解析为 `date`；当前 M19 `canonical_json_bytes` 只是 `json.dumps`，不会序列化 date。必须规定日期统一转严格 ISO 字符串后哈希，整数、容器、例外缺省等也先按确定形状规范化。否则导入时用字符串、apply 时用 YAML date，会得到不同结果或 TypeError。这是静态接缝结论，未执行该调用。

### R3：每周重复的展开边界没有闭合

涉及 §3.3、§3.6。

以下 VEVENT 均置于合法的 VCALENDAR 内；示例省去重复的外层壳。

```ics
BEGIN:VEVENT
UID:demo-weekly
DTSTAMP:20250101T000000Z
DTSTART:20250901T090000
DTEND:20250901T100000
SUMMARY:A
RRULE:FREQ=WEEKLY;BYDAY=MO
END:VEVENT
```

参数：`--school demo --label term-a --week1 2025-09-01`，学校第 1 节为 `09:00–10:00`。

**草案结果**：该 RRULE 属于承诺支持的 WEEKLY；缺 COUNT/UNTIL，也缺 `--weeks`，却要展开全部出现后取最大周次。出现集合无最大值，流程不能结束。加 `--weeks 2` 也没有解决：§3.6 把 N 定义成展开后的上界校验，而非展开截止日期。

**应有结果**：明示有限展开域及 N 的角色。最小方案是无 COUNT/UNTIL 的规则必须给 N，以 `[week1, week1+7N)` 有限展开；没有有限边界就明确报契约错误，绝不能全量迭代到日期溢出。有限规则在域外出现如何处理，也必须统一选择“拒绝”或“有提示的截取”，不能让逐次事件与 RRULE 两条路径使用不同口径。

还应规定：没有任何可导入出现、仅含被跳过事件、显式 N 与推导周数不一致时的结果。M18 可以表达空 courses，但无 N 时不能对空集合求最大周次。对普通无终止重复规则的有限处理是功能规则，不是防恶意资源耗尽的扩展。

### R4：覆盖事件必须先解析身份与取消，再决定是否跳过课程

涉及 §3.2–4。“按 RFC 替换”不足以补上当前步骤顺序。

**具体输入**：主事件使用上例，改为 `RRULE:FREQ=WEEKLY;COUNT=3`；增加同 UID 的取消覆盖：

```ics
BEGIN:VEVENT
UID:demo-weekly
DTSTAMP:20250102T000000Z
RECURRENCE-ID:20250908T090000
DTSTART:20250908T090000
STATUS:CANCELLED
SUMMARY:A
END:VEVENT
```

同样的学校和学期参数。

**草案结果**：按 §3.2 先过滤没有结束时间的事件，取消覆盖进 notes，随后展开主事件，可能得到周次 `1-3`；按 §3.3 的“按 RFC 替换”又应取消第 2 周。两条规则产生不同结果。

**应有结果**：得到第 1、3 周，取消覆盖不需要对回课程结束节次。先按 UID 建主/覆盖关系，在原始时间域按 RECURRENCE-ID 找原实例，应用取消/移动，再转换目标时区、筛选实际课程并定周次。EXDATE 删的是原实例日期，移动后的 DTSTART 决定新出现日期；不能把 RECURRENCE-ID 当成实际开课日期。

再给一个移动覆盖：RECURRENCE-ID 仍为 `20250908T090000`，DTSTART/DTEND 改成 `20250909T090000` / `20250909T100000`。应得到周一第 1、3 周和周二第 2 周，原周一第 2 周不能保留。不同 UID 的同一时间实例不得互相替换。

需明确受支持的覆盖子集：`RANGE=THISANDFUTURE` 是整段变更，不能默默只替换一次；不实现就显式拒绝。孤立覆盖、同实例多个版本、EXDATE 与覆盖同时引用原实例、覆盖省略 SUMMARY 或携带自己的 RRULE，均须有“支持且确定”或“明确拒绝”的规则。无需为 v1 实现全部日历同步协议。

结束时间也应明示支持 DTEND 或由 DURATION 推导。合法事件写 `DTSTART:20250901T090000`、`DURATION:PT1H` 时有可确定的结束时刻，不能因缺 DTEND 被误称为“没有结束时间”而丢课。至少对这一常见形式给出确定处理或显式不支持诊断。

### R5：PDF 的整星期文本流与标记计数不能保证记录边界

涉及 §4。

**合成输入一**：第 1 页有七个标签中心 `(x=100,200,…,700; y=700)`，分别为星期一至星期日。星期一带内另有：

```text
(page=1, x=100, y=610, text="A")
(page=1, x=100, y=600, text="AcademicOffice")
(page=1, x=100, y=590, text="(1-1节)1周/场地:X/学分:1")
```

其中 A 是课程名，AcademicOffice 是混入带内的表头/页眉片段。

**草案结果**：没有课程区域、表头排除和文本阅读方向规则。仅按升序坐标连接，这一合法用户空间可能先得到后缀再得到课程名而拒绝；若实现者改为顶部到底部连接，则得到 `AAcademicOffice(1-1节)…`，自由的课程名字段吸收了页眉。标记数 = 记录数 = 1，每个片段也都被“消费”，仍可错误接受串接后的名字。

**应有结果**：只有版式上确定属于同一课程单元的片段才能连接；页眉必须依据受支持的版式区域明确排除，无法定位时拒绝。坐标轴识别与坐标增长方向是两件事，规则要写出单元内阅读顺序、同一行合并方式和跨页续写条件，不能按全星期排序顺手决定。

**合成输入二**：七标签齐全，课程区只有 `A` 和 `1周/场地:X/学分:1` 两个残片，节次文本未提取出来。标记数和解析记录数都为 0；若只核计数便会成功产生空课表。草案另写“解析不出的片段报错”，这必须提升为实际的覆盖规则：除明确允许的非课程片段之外，所有课程区片段都必须归入完整记录，否则整次失败。尤其不能用“无节次标记”来把残课分类为无关文字。

补齐星期带的外边界、唯一轴判定及共线容差；后续页只有在尺寸/坐标系及版式锚点符合已支持模板时才沿用第 1 页带子。仅七个中心等距，不能保证续页发生偏移后仍正确分列。跨页文本不能无条件与另一门课拼接。

PDF 周次也不能直接照抄 §3.6 的“从日期定周次”：该解析层没有出现日期。应明确从表达式端点推导 N、再按 M18 顺序校验界限和奇偶、最后规范化周集合。例如 `1-16周(单)`，显式 N=15 时不能先过滤掉 16 再宣称未越界；缺省 N 的推导口径也须钉住。

本条不声称真实 PDF 探针已经失败。它说明现有规则不能支撑“要么正确、要么明确报错”的承诺；应把支持范围限定为可核验的模板和片段结构，补齐检查，不要求通用 PDF 理解能力。

### R6：暂存与导出必须原子发布，不能把“已存在”当作完整性证明

涉及 §2、§5、§6，AGENTS.md 已知缺陷第 1 条。

**具体输入**：第一次导入合成 ICS，写最终 `term-a--H.yaml` 时命令中断，只留下前半段；之后用相同参数重新导入。

**草案结果**：§2 规定目标已存在则不重写，没有要求先验证已有内容。允许实现者把残文件当成导入完成；apply 随后因 YAML/哈希错误拒绝。导出同理：中断留下半个 `.ics`，下一次立即因存在而拒绝。

**应有结果**：最终可见文件只能是完整文件。先在同目录忽略区域写临时文件，关闭并重读校验，再用 `os.link(临时, 目标)` 不覆盖发布，清理临时文件；不要用 exists 后 replace，也不要把 M19 可替换的生成包写法直接移植到本端口不可覆盖的文件。

暂存目标已存在时，只能在内容经过验证且符合已规定的重复导入语义时视为成功；不同内容或无效内容明确报错，保留原文件，不偷偷覆盖人工编辑。notes 不参与哈希，但文件重复判定是否比较 notes 也需明确。

**apply 顺序本身可保留**：读取并校验旧字节、候选和学校 → 准备新规范字节 → 发布旧字节备份 → 原子替换主文件。备份发布前中断，主文件不变；备份后替换前中断，主文件不变且有完整备份；替换完成后中断，主文件完整且旧备份仍在。不要为后一个状态再设计强行恢复旧表的回滚。

但需把“同一份原始字节只读一次用于解析、哈希、备份”、已有备份同名不同内容则拒绝、备份失败不得替换主文件、新字节在写入前校验、普通 I/O 错误转契约错误写成要求。当前 replace_bytes 提供目录项原子替换，不承诺硬断电的完整持久化事务；本轮不额外要求数据库式事务或跨文件日志。

### R7：候选学期校验缺少 M18 可直接调用的公开端口

涉及 §3.8、§5.3、D7。

**具体输入**：学校 demo 只定义第 1 节；暂存学期有 `periods: "2"`、`weeks: "1"`，其余字段有效。或者只有有效的 semester 对象，没有个人课表 rules。

**草案结果**：要求通过 M18 `load_timetable` 校验“学期、课程、节次存在”。当前该公开函数只接受完整 M18 文件（含 rules），只做文件内校验；不会核对学校引用或节次存在。文件形状正确但节次不存在的整份课表可通过它；直接把 semester 交给它则不是所需文件形状。

正式引用校验目前在 `timetable_for_workspace` 内完成，读取的是已生效 state.timetable；拿它校验尚未写入的合并对象，也不能自动完成草案流程。实现者若写进生效文件后再验证，会违反“失败不写”；若跨模块 import `_timetable_from_mapping` / `_load_referenced_schools`，则违反 D7。

**应有结果**：规格明确提供公开的候选数据校验/日历构造口，接受规范候选对象和一次加载的学校资料；或明确一种通过现有公开函数、隔离文件及候选 Workspace 完成的流程。不得复制校验规则，不得读取旧表冒充校验新表，不得先改生效表。导入可在只登记学校、未登记个人课表时校验一个 semester；apply 校验合并后整份表及引用后才能写入。

本条不要求改变 M18 计算语义。“M18 不改”宜解释为适配器新增不改变 M18 的业务格式与计算；若连补公共校验入口也禁止，就必须把替代调用办法写全。

### R8：跨课间空档的课程不能作为整个首末跨度的忙碌事件

涉及 §6 与 M18 §4.4、§7。

**具体输入**：学校两节分别 `09:00–10:00`、`13:00–14:00`；周一 A 占 `1-2` 节。学习窗 `08:00–16:00`，缓冲、最短空档和扣减都为 0，上限 480。导出该周一，两个事件类别都选。

**草案结果**：课程 VEVENT 为 `09:00–14:00`；M18 同时给出空闲 `10:00–13:00`，导出也产生这一学习时段。日历中的课程事件把三小时真实空档包在课程跨度内。

**应有结果**：课程的实际占用分段导出，至少不得把不连续的节次间空档标成上课。最简单是逐节导出、只合并时间相接的节；若保留首末跨度作为展示摘要，必须显式作为透明事件，另行明确真实占用的表达。不能直接把 M18 标为“只作展示”的 classes 首末时刻升级成忙碌区间。

M18 的 free_segments 保持原样，不因日历导出重新扣一次课程或午休，也不按参考分钟裁短物理空档。这是正常连堂跨长休息段的展示/占用问题，不是要求本轮把任务按时段排程。

## 二、ICS 边界与可保留规则

以下是规则判断，未运行解析器。完整输入需要合法 VCALENDAR 壳、UID、DTSTAMP 等；示例内容没有真实课表信息。

| 合成输入 / 参数 | 应明确的结果 |
|---|---|
| A 的逐次事件分别在 2025-09-01、09-08、09-15，均 09:00–10:00；week1=09-01 | 一门周一 A，weeks=`1-3` |
| 同 A 改为 WEEKLY COUNT=3 | 与上行相同；DTSTART 是首个实例，不能 COUNT 之外再额外加一次 |
| 上行加 `EXDATE:20250908T090000` | weeks=`1,3`；多个 EXDATE 属性及一个属性的多个值均应处理 |
| 移动覆盖由周一第 2 周移到周二第 2 周 | 原实例删除，新实例按实际日期分组，见 R4 |
| `INTERVAL=2;COUNT=3`，首日 09-01 | 周一 weeks=`1,3,5`，不是第 1、2、3 周 |
| `BYDAY=MO,WE;COUNT=3`，首日周一 09-01 | 周一第 1、2 周，周三第 1 周；COUNT 计全部出现而非每个 weekday 各计三次 |
| WEEKLY UNTIL | 明示 UNTIL 的类型/时区要求与包含末次的边界，按原始 recurrence 时间域展开后转换；不能拿目标本地午夜直接替代 |
| DTSTART/DTEND 为 `20250831T233000Z` / `20250901T003000Z`，timezone=Asia/Tokyo；学校有 08:30–09:30 | 转换后均在 09-01，应该可对回节次；跨日判定要在目标本地日期上做，不能因原始 UTC 跨日先跳过 |
| 浮动 09:00–10:00，给或不给 timezone | 都保持墙上时间；不得把浮动值擅自当 UTC 再转换 |
| 带 TZID/UTC 而没给 timezone | 明确拒绝，合理；无法解析的 TZID 也拒绝，不能退成浮动 |
| 起点 `09:00:30`，学校 start=09:00 | 精确匹配失败；不能截去秒后误收 |
| 两个独立 UID，同一 SUMMARY/日期/节次 | 按已选分组口径属于重复，明确拒绝合理；不同 SUMMARY 的真实冲突仍由 M18 允许并提示 |
| SUMMARY 只有空白 | strip 后为空，拒绝；LOCATION、教师等不进入课程键，符合最小化数据选择 |
| RDATE 或不支持 FREQ | 显式拒绝合理；不能只忽略属性后导入 DTSTART，假装全部导入 |
| 全天、转换后跨日或真正无可确定结束时间的事件 | 可 notes 跳过，但提示须可见；如最终没有课程，走 R3 的明确空结果规则 |

§2 说“外部文件不表达调休”不准确：逐次 ICS、EXDATE、移动覆盖完全能表达实际取消和补课。应改成“导入把实际出现规范化进课程周次/星期，不生成 M18 exceptions”。正常补课移到其他星期会成为另一条课程，不必人为造 follow。

## 三、导出兼容性与确定性建议

1. **学习时段的 TRANSP**：free_segments 表示可用窗口，不是已安排任务。建议明确 `TRANSP:TRANSPARENT`，否则常见日历忙闲视图可能把所有可学习窗口当成忙碌。若决策者确实想预占学习块，要在规格明说，不能让序列化默认值替用户选择。
2. **UID 与重复**：建议把事件类别及分段身份纳入结构化哈希，明确完全相同课程出现是去重还是保留；保留时不能生成两个相同 UID。当前“日期|起|止|SUMMARY”对 M18 允许的相同记录没有区分。摘要截断的极小碰撞概率不作为本轮返工理由。
3. **完整排序及编码**：时间相同的事件补次级键；UID 哈希字段的编码/分隔或规范 JSON 口径、UTF-8、CRLF、文本转义、行折叠、VCALENDAR VERSION/PRODID 写进契约，交给 icalendar 处理。固定依赖版本或明确版本升级后的字节基线口径。
4. **浮动时间可以保留**：这是明确标注的拟定项，利于不需要时区的本地课表；提示其跟随显示设备时区，并不等于带地理时区的同一绝对时刻。无须本轮增加在线订阅或凭据功能。
5. **日期范围空状态**：明确反向范围、相等端点、未登记课表、范围完全不覆盖学期的退出码与是否写合法空日历；两个 only 选项互斥。这样实现者不会自行选“报错”还是“写空文件”。
6. **基数与物理空档**：本包导出的时段应复用同一日历的 day；当前 cap 变化不会改变物理 free_segments。不要为导出再次实现 M8/M18 算法或按 daily minutes 重新分配空档。将来逐日基数接入，沿同一公开解析端口取值即可。

## 四、apply 与格式的其他建议

- **重跑语义**：备份完成、替换尚未发生时，可使用同一旧哈希备份重试。替换完成但成功输出前中断，普通追加再跑会遇到 label 冲突；建议若候选与已生效学期完全相同则返回“已应用”，或者明确指导先查看、无需再次替换。没有必要增加 applied 清单或双文件事务。
- **规范写出范围**：规定只替换/追加指定学期，保持其他学期顺序与 rules 值；丢注释、备份位置在 dry-run 摘要里也显示。规范序列化可重排格式，不能无意改变未涉及课程的语义。
- **差异键**：新增/删除/周次变化按 `(name, weekday, first_period, last_period)` 比较；星期/节次改变应明确视为删旧增新。exceptions、学校或锚点变化也要在摘要中可见，不能课程差异为零就让用户误认为没有变化。
- **§2 字段表**：补 schema 精确整数、kind、adapter 枚举、64 位小写十六进制 source.sha256、notes 的类型、未知/重复键拒绝、课程/例外顺序及缺省形状。source 原始字节摘要来自一次读取，不记录源文件路径。
- **label 作为文件名**：M18 label 只要求非空，可能含 `/` 或 Windows 不允许的字符。选择可逆编码或纯摘要文件名，不要把完整 label 直接拼路径，也不要悄悄收紧所有 M18 学期名的语法。
- **依赖**：icalendar、python-dateutil 都显式声明，不能依赖后者恰好是某个版本的传递依赖。本机是 Windows，时区数据的获得方式也应明确（例如项目声明 tzdata），避免安装后只有浮动时间路径能用。

## 五、用户选择与 D7 裁定

| 项目 | 裁定 |
|---|---|
| ICS 优先，正方 PDF 备用 | 一致；不要求 PDF 成为通用解析器 |
| 先进暂存，用户 apply 生效 | 一致；R2/R6 补齐后才成为完整可用流程 |
| 导出在 ④b | 一致；不是线上订阅服务，§9 排除在线服务合理 |
| 不经手账号密码 | 合理范围限制，没有加入用户未选的抓取路线 |
| 个人文件都不进 Git | §1/§8 一致，但 §6 提醒后继续写与之冲突，见 R1 |
| 精确时刻匹配 | 合理拟定项；能发现学校作息不一致，不加入分钟容差猜测 |
| 规范化周表达式 | 合理，升序合并连续周可唯一表达有效集合；原表达式越界检查须先做 |
| 规范重写丢注释但留原始备份 | 可接受拟定项；明确预告、原始字节备份、写前全部校验即可 |
| 浮动时间、out 必填、不覆盖 | 可保留；补发布与日历忙闲语义，不必替换为自动选择输出路径 |

两层 PDF 设计符合 D7，但片段值最好还包含页尺寸/变换信息、原片段身份和可追溯范围，以便版式校验、覆盖核对及错误定位。解析层只负责外部记录；公共规范化层负责周次、分组、排序和暂存封装；apply 负责工作区校验与存储；export 只消费 M18 结果。适配器之间共享规范化层即可，不应把 RRULE、PDF 正则塞进 M18，也不应跨模块使用 M19 私有路径辅助。

可复用 M19 的公开 canonical_json_bytes，但日期转换和候选结构属于 M29/M18 的明确端口。路径两步包含检查可照现有写法在 M29 中建立具名小辅助，或经单独公共端口抽取；不能 import `_resolve_staging_path`。新增模块在决策者收口时登记模块地图。

## 六、安全登记

1. **短摘要与人工篡改**：hash12 是文件名定位/一致性检查，不是授权或完整的抗篡改承诺；notes 本来不参与摘要。恶意修改暂存、构造摘要碰撞或伪造来源属于既定安全登记范围。本轮不要求数字签名或身份认证。可保留完整摘要供将来加强核验。
2. **恶意链接及超大输入**：导入目标、备份和导出可能被恶意链接重定向，外部文件也可能恶意制造极大有限展开或复杂 PDF。保留既有包含检查和不覆盖发布；进一步防并发、防资源攻击留安全登记。R3 的无终止普通 RRULE、R6 的命令中断不属于此豁免。

没有读取攻击样本或运行安全探针；以上是规格边界登记，不是已测漏洞结论。

## 七、是否足以实现

**尚不足。** 应先关闭 R1–R8，尤其确定有限展开、覆盖处理顺序、PDF 单元边界、人工编辑重封装以及公开候选校验端口。建议项中日期空状态、暂存字段类型和差异键也宜在实现任务书明确，避免实现者替决策者选口径。

验收建议只覆盖上述实际规则缺口的合成输入、重复导入及发布/替换边界的中断；真实 PDF 集合等价仍由决策者在本机核对，报告只留脱敏结论。不要把真实 PDF、课程集合或个人标签写进公开夹具和报告。
