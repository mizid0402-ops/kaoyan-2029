## 但先做一件事：判断数学一**到底需不需要加权**

**这是本任务的前置判断，不要跳过。**

加权合并要有意义，前提是**来源之间存在真实分歧**。所以先判断：

| 问题 | 为什么要问 |
|---|---|
| 数学一考纲的结构是**定死**的吗？ | 若像英语一那样"22 章、每章考点固定"且历年不变，那**单源足够**，不需要加权 |
| 数学一的**条目会随年份变化**吗？ | 若会（如某章新增/删除考点），那**需要第二份来源来判"是真变还是转录错"** |
| 现有那份 2022 转录的**已知问题**是什么？ | 它是第三方转录，可能含 OCR/转写错误 |

**任务书要求你先给出这个判断，再决定检索方向。** 如果结论是"数学一不需要加权"，
那本任务就只需回答"单源够不够、有什么风险"，**不需要硬找第二份**。

## 判据（用户已修正，务必遵守）

三条**互不推导**的轴：

| 轴 | 问什么 |
|---|---|
| **① 权威性** | 谁发布的——**只用于"能否定义考纲"这一件事** |
| **② 准确性** | **对不对**，必须给**可交叉验证的数字**（如与现有转录的章标题一致率、条目数对比） |
| **③ 可传播性** | 能否落盘 / 再分发，**分开答** |

**关键纪律（上轮英文检索者自己总结的，直接沿用）：**

> **"非官方"只降低"能否定义考纲"的权威性，不自动推导出"不准确"或"不可本地使用"；
> 同样，MIT 代码许可也不自动覆盖仓库内第三方教材、PDF、题干或派生数据。**

**所以：不要因为非官方就把候选判死。** 非官方能用就用，如实标等级；
权利不明标 `unknown`，但可用"仅本地自用"落地。

## 硬性要求

### 1. 必须实际下载并核对，不能只看 README

- 记录 URL、字节数、**SHA-256（现算）**、发布者自述、许可声明
- **抽样核对内容**：**只列字段名与条目数**，不要抄录考纲正文
- 若是 PDF 且无文本层，用 `pypdfium2` 渲染后目视读

### 2. 必须给**可测量的准确性数字**

对每个候选，若能与现有来源比较，算出：

- **章标题一致率**（Jaccard）
- **章节数 / 条目数**对比
- 一致 / 只在一边的条目数

**这些数字才是"准不准"的依据**，不是来源等级。

### 3. 必须区分"同一版本的独立转录"与"不同年份的版本"

**这是加权合并可行性的关键。** 请在报告里明确写出：
- 你找到的候选，与现有来源是**同一版本的独立转录**，还是**不同年份的版本**？
- 各自能支撑什么结论、不能支撑什么？

### 4. 找不到就说找不到

**绝不用模型自己的知识"生成"一份数学一考纲冒充检索结果。**

**如果最终结论是"数学一不需要加权、单源足够"，那也是有价值的答案，如实写。**
**如果结论是"需要第二份但确实找不到"，同样如实写，并说明缺什么。**

### 5. 不要抄录受版权保护的正文

报告里只列：repo/URL、字段名、条目数、许可、结构描述、章标题（**章标题是短标签，可列**）。
**不要抄**：考纲正文段落、考点描述全文、例句。
