## 1. 读取口径

- **[读-题面]**：直接从 PDF 文本层或渲染 PNG 目视读到。
- **[读-网页]**：直接从 HTML 正文、页面标题或页面字段读到；不把它自动升级为原卷事实。
- **[读-字段]**：从结构化题库的 `score` 字段读到；若与同一条记录的题干冲突，分别保留。
- **[算术校验]**：只做加法与一致性检查；不通过 `70-其他六题` 补任何分值。
- “题头”仅指题目前的 `(本题 N 分)` / `(N 分)`；小问合计不冒充题头。

### 2.1 44 题冲突的逐字校验

static p22、pipihui p16、iqihang p8 的题面顺序均为：

1. `(1) ... (1 分)`；
2. `(2) ... (2 分)`；
3. `(3) ... (4 分)`；
4. `(4) 左移指令周期中四个信号... (4 分)`；
5. 紧接同一编号 `(4)` 的第二个评分点：`Extop 是否可以与 M 型指令中的 EXTop 相同？为什么？(4 分)`。

因此 **[算术校验]** `1+2+4+4+4=15`。csgraduates/N诺 HTML 把第 (4) 问末尾转写成 2 分，CodeBrick 把整个第 (4) 问合并成 7 分；两者都弱于可直接目视的题面。

### 2.2 45 题的 `7` 与 `10` 不是同一种证据

- **[读-网页]** CodeBrick `os-2026-45` 的题干第一行写“本题满分 7 分”，小问写 5、2。
- **[读-字段]** 同一 CodeBrick 记录的顶层 `score` 字段却是 10。
- **[读-题面]** 三份 PDF 均只印 5、2，不印总分。

所以 CodeBrick 路线中的“45=10”是题库字段值，不是题面题头读数；同一记录内部已经被题干 `7=5+2` 反证。
