# 任务：构建 408 **加权知识树**

## 为什么 408 需要加权，而英语一不需要

加权合并要有意义，前提是**多个来源在某处存在真实分歧**。408 正是这种情况：

| 分歧类型 | 实例 |
|---|---|
| **章被改名** | 2022「操作系统概述」 vs 2026「操作系统基础」；2022「线性表」 vs 2026「基本概念」；网络 2022「计算机网络体系结构」 vs 2026「计算机网络概述」 |
| **条目拆分/合并** | 组成原理 2022 把"条目+说明"合成一条，2026 拆开；网络 2022 一条 vs 2026 拆成"标题 + detail" |
| **条目单边出现** | 只在 2022 有 59 条；只在 2026 有 60 条 |
| **疑似真新增** | `堆及其应用`、`多处理机调度` |
| **OCR 风险词** | `Cach`（Cache）、`页椎`（页框）、`1/O`（I/O）|

**所以本任务的核心是：把这些分歧按证据强度打成权重，产出一棵"带权重的树"。**

## 你要做的

### 1. 建加权树

在 `data/structured_materials/cs408/` 下新建（**不要覆盖现有 `knowledge_tree.yaml`**）：
`knowledge_tree_weighted.yaml`

每个节点至少带：

| 字段 | 说明 |
|---|---|
| `knowledge_point_id` | 沿用现有命名规则 |
| `title` | 采用**源 A（2026）**的措辞为准，另存别名 |
| `aliases` | 其他源里的同义标题（如 2022 的「操作系统概述」） |
| `sources` | 出现该节点的来源列表（A / B / C） |
| `source_count` | 支持它的来源数 |
| `weight` | 按上表建议 |
| `evidence_tag` | 上表的标签之一 |
| `scope` | subject / chapter / section / item |
| `status` | **见第 3 节的状态规则** |

### 2. 处理好四类对应关系（这是本任务的技术核心）

| 关系 | 处置 |
|---|---|
| **章改名** | 判为**同一章**（同位置 + 内容重叠），标题取源 A，2022 的写法进 `aliases`。**不要因为字面不同就当成两个章** |
| **条目拆分/合并** | 用**"位置 + 内容包含"**判对应，不是字符串相等。一条对多条时，**逐条给权重并记录映射关系** |
| **单边条目** | 按建议表给 0.50 / 0.75，**并标注待核原因** |
| **OCR 风险词** | `Cach`/`页椎`/`1/O` 等：**保存原始标题与修正候选两套**，**禁止静默改写来源原文** |

### 3. 状态字段的规则（重要，别搞错）

- **`approved` 不要用**——它要求 `actor=human`，本流程无权产生
- 用 `extracted` 或 `reviewed`，并在文件头明确写：
  **"本树为多源加权基线，非人工核准；权重反映来源支持度，不反映正确性"**
- 每个节点带 `weight` 与 `source_count`，**让下游能自己判断可信度**

### 4. 用源 C 做**独立的第三方印证**

- 从 `408_questions.json` 抽出 2009–2025 各年的 `knowledgePointIds`
- **统计每个知识点被考到的年份数与次数**
- 与树节点对照：
  - **树里有、源 C 从没考过的节点** → 列出（**不删除**，但标注）
  - **源 C 有、树里找不到的考点 id** → 列出（**可能是树缺节点**，这是重要信号）
- **注意**：源 C 的考点 id 体系可能与我们不同，**需要先判断能否映射**。
  映射不上就如实说"无法映射"，**不要硬凑**

### 5. 与现有 403 节点树的关系

- **保留现有 `knowledge_tree.yaml` 不动**（它是单源基线）
- 加权树里要能看出**每个节点相对单源基线是"新增/保留/降权"**
- 一致性校验：加权树的节点集合 ⊇ 现有树？差异在哪？

### 6. 验证与测试

- 独立验证脚本：权重是否按建议表、`source_count` 是否与 `sources` 长度一致、
  aliases 是否真在对应来源里出现过
- **变异测试**：改一个权重、删一个 source、把 aliases 写成源里不存在的字符串 → 必须变红；给还原哈希
- `py -3.12 -m unittest discover -s tests -q` 必须全绿（先记录开工前基线）
- 报告 `review/rounds/round-24-408-weighted-tree-claude.md`

## 报告必须包含
